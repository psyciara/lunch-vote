# 역량평가 과제 개발 포털 기능 명세

- 버전: 4.1 (2026-11-12)
- 화면은 `ac-studio.html`(화면 시안)을 본다. 이 문서에는 화면에 드러나지 않는 처리, 규칙, 데이터만 적는다.
- 시안의 AI 응답·파일 변환은 예시 값이다. 실제로 연결할 곳은 시안 코드에 "API 연결 지점" 주석으로 표시했다.

---

## 1. 개요

사내 서버에 설치한 오픈소스 AI 모델로 역량평가 과제 개발을 돕는 사내 포털이다.

| 단계 | 넣는 것 | 나오는 것 |
|---|---|---|
| ① 주제 탐색 | 발주처, 직급, 평가 기법 | 해결과제명·측정 역량, 스토리맵 |
| ② 과제 초안 | 스토리맵, 참조 평가과제, 참조 평가자가이드 | 평가과제(pptx), 평가자가이드(pptx 또는 docx) |
| ③ 검토회의 보고서 | 회의 녹음 파일, 보고서 양식(hwpx) | 검토회의 결과보고서(hwpx) |
| ④ 검토의견 반영 | 평가과제 pptx, ③ 보고서 | 고친 평가과제 pptx, 반영 내역표 |
| ⑤ 검수 | 평가과제 pptx, 평가자가이드 | 고친 pptx, 검수 결과표(엑셀) |

| 전제 | 내용 |
|---|---|
| 처리 위치 | 언어 모델, 이미지 생성, 음성 인식, 화자 구분, 파일 변환을 모두 사내 서버에서 한다. 외부 AI API는 쓰지 않는다. |
| 권한 | 이용자(과제 개발 담당자), 관리자(이용자 기능 + 관리자 화면). 관리자 화면은 서버에서도 권한을 확인한다. |
| 작업 단위 | 과제 1건 = 프로젝트 1개. 앞 단계 결과를 다음 단계가 그대로 받아 쓰고, 어느 단계부터든 시작할 수 있다. |

## 2. 공통 처리 규칙

### 2-1. 처리 규칙

| 규칙 | 내용 |
|---|---|
| AI 결과는 제안이다 | AI가 고친 안은 따로 보관하고, 이용자가 [반영]할 때만 문서를 바꾼다. [다른 안 제안받기]는 같은 요청으로 다른 안을 받는다. |
| 모든 수정은 기록한다 | 수정마다 항목, 바꾸기 전·후, 누가(이용자/AI), 이유(요청 문장·점검 항목)를 남기고, 아무 기록이나 되돌릴 수 있다. |
| 숫자는 코드가 계산한다 | 합계, 비율, 증감률, 날짜·요일, 표·차트 숫자 읽기("410만 건" → 410, 단위 "만 건")는 계산 코드가 한다. AI는 어느 숫자끼리 맞아야 하는지만 찾는다. |
| 영향받는 곳을 알린다 | 숫자나 사실을 고치면 같은 내용을 쓰는 다른 항목과 평가자가이드 부분을 찾아 "함께 확인 필요"를 붙인다. |
| 앞 단계 수정은 다음 단계로 이어진다 | 예: ③ 보고서 문장을 고치면 ④ 수정 요청 목록에도 반영한다. |
| 양식·구조를 고정하지 않는다 | 보고서 양식, 과제 파일의 방향·쪽 크기·자료 개수·자료 표기는 용역마다 다르다. AI가 구조를 제안하고 이용자가 확인한 것을 용역별로 저장해 다시 쓴다. |
| 지침은 관리자가 관리한다 | 기능마다 쓰는 지침(4-2)과 점검 항목(4-3)을 고치면 모든 이용자에게 바로 적용된다. |
| 자동 저장 | 작업 내용은 자동 저장한다. |
| 단계 완료 | ②: 점검을 한 번 이상 돌리고 남은 점검 결과가 없을 때. ⑤: 점검 결과가 하나 이상 있었고 남은 결과가 없을 때. 나머지 단계는 결과물을 만들면 완료. |

### 2-2. 지침이 바뀌어도 포털이 그대로 돌아가게

기능마다 넣는 스킬과 지침은 관리자가 언제든 바꾸거나 새로 올린다. 포털은 특정 지침의 내용에 기대지 않고, 정해진 연결 방법으로만 지침을 쓴다.

**누가 무엇을 정하나**

| 구분 | 정하는 곳 | 예 |
|---|---|---|
| 포털이 고정 | 개발(코드) | 반영·되돌리기 흐름, 수정 기록, 계산 코드, 파일 읽기·쓰기, 권한, 화면마다 받을 결과 틀 |
| 지침이 정함 | 스킬·지침 파일(관리자가 바꿈) | 단계 수와 이름(★정지), 이용자에게 물을 질문, 후보 수, 판단 기준(겹침, 자리 제안, 점검), 문장 문체 |
| 관리자가 정함 | 관리자 화면 | 기능별 지침 연결, 확인 단계의 화면 표시 이름, 다른 지침으로 보내는 곳, 개수 상한, 양식, 점검 항목 |

**규칙**

| 규칙 | 내용 | 이유 |
|---|---|---|
| 지침 내용을 코드에 적지 않는다 | 단계 수, 후보 수, 질문, 판단 기준, 문체는 지침에서 읽는다. 이 문서에 "현재 지침: …"으로 적은 값은 지금 지침의 예시일 뿐 코드에 넣을 값이 아니다. | 같은 값을 코드에도 두면 지침을 바꿔도 화면이 따라오지 않는다. |
| 결과 틀로 받는다 | 포털은 지침 뒤에 그 화면이 받을 결과 틀(칸 목록, 예: 후보 = 해결과제명, 측정 역량, 내용, 겹침 판단, 가까운 기출)을 붙여 보낸다. 결과 틀에 없는 내용은 "추가 내용"으로 받아 접힌 자세히 보기에 보인다. | 지침이 바뀌어도 화면이 받는 모양은 같아서 깨지지 않는다. |
| 개수는 결과에 따른다 | 후보, 질문, 확인 단계, 점검 결과, 제안은 받은 만큼 보여 준다. 화면이 개수를 정하지 않는다. | 지침에서 후보를 3개로 줄이면 화면도 3개가 된다. |
| 지침 파일에서 직접 읽는 표시는 ★정지 하나다 | 제목 끝의 "★정지"를 찾아 확인 단계를 만든다(4-2). 그 밖의 연결은 결과 틀로 한다. | 지침을 쓰는 사람이 지킬 약속을 최소로 둔다. |
| 지침 이름·경로를 코드에 적지 않는다 | 다른 지침으로 보내는 곳(예: 검토 교훈을 넣을 파일)과 개수 상한(예: 자료당 그림 수)은 관리자 설정이다. | 지침 이름이나 파일 구성이 바뀌어도 설정만 고치면 된다. |
| 과제마다 쓴 지침 버전을 남긴다 | 단계를 돌릴 때 쓴 지침과 버전을 프로젝트에 기록한다. 지침을 저장할 때 관리자가 "새 과제부터" / "진행 중인 과제에도(다음 단계부터)"를 고른다. 진행 중인 과제에 적용되면 이용자에게 "지침이 바뀌었습니다(v5 → v6). 다음 단계부터 새 지침을 씁니다"를 알린다. | 과제 도중에 규칙이 몰래 바뀌지 않게 하고, 결과물이 어떤 지침으로 만들어졌는지 추적한다. |
| 결과 틀을 못 채우면 그 자리에서 알린다 | 지침이 없거나 결과가 결과 틀의 필수 칸을 채우지 못하면 실패 화면(무엇이 빠졌는지, [다시 시도])을 보인다. | 지침이 바뀌어 생긴 문제를 이용자가 엉뚱한 결과로 받지 않게 한다. |

## 3. 이용자 기능

### 3-1. ① 주제 탐색 (지침: `ac-topic-storymap`)

| 기능 | 처리 |
|---|---|
| 조건 목록 | 발주처·직급 목록은 기출 DB와 주제풀(4-4)의 값으로 만든다. 직급은 고른 발주처의 값만 보인다. |
| 평가 조건 찾기 | 같은 발주처·직급·기법의 기출에서 해결과제 수, 해결과제별 측정 역량, 업무 관련성, 가상조직 기관 유형을 찾는다. 항목마다 근거 파일명과 근거 종류(지침이 정한 표시. 현재 지침: [DB 확인] / [설정 문서] / [추론] / [확인 불가])를 붙인다. 같은 조합의 기출이 없으면 이용자가 직접 정한다. |
| 스킬의 질문 | 스킬이 이용자에게 묻도록 정한 질문(예: 채택되지 않은 제안 주제도 피할지)은 추천값과 이유를 붙여 묻고, 답해야 다음으로 간다. |
| 구조 분석 재사용 | 기출 구조 분석 결과를 용역 설정(4-4)에 DB 기준 정보(행 수, 최근 연도, 서명)와 함께 저장한다. 다음에 DB 기준 정보가 같으면 분석을 건너뛴다. |
| 후보 만들기 | 해결과제마다 지침이 정한 수만큼 후보를 받는다(현재 지침: 서로 다른 분야 5개, 두 번째 해결과제부터는 고정한 가상조직이 맡을 만한 업무). |
| 겹침 판단 | 후보를 기출 DB, 발주처 주제풀, 실무 DB와 대조해 겹침 여부와 가장 가까운 기출을 붙인다(판단 기준은 지침). 겹칠 수 있는 후보를 고정하면 한 번 더 묻는다. |
| 스토리맵 | 전체 확정(발주처, 가상조직, 해결과제 목록) 승인 뒤에만 쓴다. 형식은 지침을 따른다(현재 지침: 역량-내용 연계 분석 표를 함께 만듦, 내부 검토용). |
| 근거 파일 보기 | 근거 파일명을 누르면 서버 파일에서 찾은 부분과 파일 위치를 보여 준다. |

### 3-2. ② 과제 초안 (지침: `isomorph-ac`)

| 기능 | 처리 |
|---|---|
| 확인 단계 | 스킬의 ★정지 표시마다 멈추고 결과를 보여 준다. 이용자가 확인해야 다음 단계를 요청한다. 단계 수와 순서는 스킬을 따른다. |
| 화면 표시 이름 | 확인 단계와 스킬 용어는 관리자가 정한 화면 표시 이름으로 보인다(4-2). 스킬 본문은 그대로 둔다. 현재 값: A1/A2/B1 → 예전 과제 풀이 다시 보기 / 새 과제 풀이 짜기 / 자료 나누기, 판별 지점 → 핵심 판단 지점. 이름을 정하지 않은 새 단계는 스킬의 제목을 그대로 보인다. |
| 출력 | 평가과제 pptx, 평가자가이드(참조 가이드와 같은 형식: pptx 또는 docx). 방향, 쪽 크기, 레이아웃, 글꼴은 참조 평가과제를 따른다. |
| 과제-가이드 연결 | 가이드의 정답 근거마다 과제의 자료·쪽을 연결해 둔다(2장 "영향받는 곳을 알린다"에 씀). |

### 3-3. 편집 (②④⑤ 공통)

| 기능 | 처리 |
|---|---|
| 파일 이어받기 | ④⑤는 앞 단계 결과(평가과제와 평가자가이드)가 있으면 그대로 쓴다. 새로 올린 pptx는 아래 나누기를 거친다. |
| pptx를 항목으로 나누기 | 모든 글상자(그룹 도형 안 포함)에서 자료 표기("자료 3.", "[자료 3]", "<자료 3>", "참고자료", "붙임")를 찾는다. "(1/4)", "계속" 표시가 붙은 연속 슬라이드는 한 자료로 묶는다. 글만 있는 간지("역할별 자료", "평가대상자 A")는 구분의 시작, 간지가 없으면 "공통 자료". 표지·안내·상황개요·가상조직·마침은 "구조". 인쇄 쪽 번호("- 6 -", "6/20")를 위치 표기에 쓰고, 없으면 슬라이드 순번. |
| 목차 규칙 저장 | 이용자가 확인한 나누기 결과를 용역별 목차 규칙(4-5)으로 저장해 같은 용역의 다음 파일에 먼저 적용한다. |
| 고칠 범위 | 선택한 글, 항목 하나, 여러 항목, 과제 전체. 범위 안의 글과 요청을 보내 항목마다 고친 안을 받는다. [전체 수정 제안]은 요청 없이 과제 전체에서 고칠 곳을 찾는다. |
| 점검 | 점검 항목(4-3)의 지침 + 문서 전체를 모델에 보내고, 계산 코드를 쓰는 항목은 코드 결과와 합친다. 결과마다 위치(찾은 글자), 이유, 고친 안. |
| 내보내기 | pptx는 글상자의 글과 그림만 바꿔 끼우고 레이아웃·글꼴·표 모양은 원본 그대로 둔다. |

### 3-4. 그림·지도·차트 (지침: `ac-figure`)

| 기능 | 처리 |
|---|---|
| 그림 자리 | 항목 본문에 한 줄로 적는다: `[그림] 제목: 설명`, `[차트] 제목`. 제목에 "지도·위치도·배치도"가 있으면 지도. 넣기·옮기기·빼기는 이 줄을 고치는 것이므로 수정 기록과 되돌리기가 그대로 적용된다. 새 자리를 만든 직후 만들기를 취소하면 빈 자리를 지운다. |
| AI 자리 제안 | 고칠 범위 안 항목 글, 평가자가이드, 자료당 상한(4-5)을 보내 결과 틀(종류, 위치, 제목, 내용, 이유, 가정)로 제안 목록과 제안하지 않은 곳·이유를 받는다. 어디에 무엇을 제안할지는 지침이 정한다(현재 지침: 평가자가이드가 채점하는 값은 차트로 만들지 않음 등). 포털은 자료당 상한만 코드로 한 번 더 지킨다. |
| 그림 만들기 | 지침으로 장면 설명을 쓰고, 느낌·비율을 붙여 이미지 생성 모델로 4장을 만든다. 그리지 않을 것은 지침이 정한다(현재 지침: 실존 인물, 실제 기관 로고·상표, 알아볼 수 있는 실제 장소, 그림 속 글자). |
| 지도 만들기 | 평가과제 자료 글 전체와 사용 중인 지도 범례 항목(4-5)을 보내 초안을 받는다. 뽑을 항목의 기준은 지침이 정한다. 원고에 근거가 없는 항목은 "가정"으로 표시하고, 가정 항목을 이용자가 확인하기 전에는 넣지 못한다(확인 뒤 가정 항목이 새로 생기면 다시 확인). 작업 파일(JSON)과 SVG를 프로젝트에 저장해 다시 열어 고친다. 내보내기: SVG, PNG, 작업 파일. |
| 차트 만들기 | 프로젝트 안의 표를 계산 코드로 읽어 숫자·단위를 가져온다. 차트 종류 추천은 지침이 한다. 넣는 방식은 포털이 정한다: 세로 막대, 가로 막대, 누적 막대, 꺾은선, 원은 PPT 차트(python-pptx, PowerPoint에서 값을 고칠 수 있음)로, 막대+꺾은선은 PNG + 데이터 표로 넣는다. 평가자가이드(docx)에는 PNG. |
| 파일 올리기 | png, jpg, svg를 그대로 넣는다. |

### 3-5. ③ 검토회의 보고서

| 기능 | 처리 |
|---|---|
| 녹취록 | 음성 파일(mp3, m4a, wav)을 글로 바꾸고 화자를 나눈다(3~5명, 자동 가능). 결과: 화자 번호, 발언 시각, 발언 내용. |
| 화자 정보 | 화자마다 이름, 소속, 구분(검토위원 / 발주처 / 개발사)을 받아 그 화자의 모든 발언에 적용한다. 구분이 빠진 화자가 있으면 칸을 채우기 전에 알린다. |
| 양식 읽기 | hwpx 양식에서 채울 칸을 찾는다. hwp는 읽지 않고 "한글에서 hwpx로 다시 저장"을 안내한다. 칸마다 AI가 채움 / 비워 둠 / 직접 입력. |
| 칸 채우기 | 검토위원 의견, 발주처 의견(관련 발언이 없는 행만 비움), 개선 및 반영 방향을 녹취록에서 채운다. 문장 문체는 지침과 양식의 이전 회차 내용을 따른다(현재 지침: "~하겠음"). 회의내용 표의 "위치 행 + 내용 행" 묶음은 의견 수만큼 늘린다. 참석인원은 화자 정보, 건명·일시는 프로젝트 정보와 녹음 날짜로 채운다. |
| 문체·위치 표기 | 양식에 이전 회차 내용이 있으면 그 문체와 위치 표기(예: "[자료3. 제목(2/3), 6page]")를 따른다. 평가과제 pptx를 함께 고르면 "자료 3 두 번째 장" 같은 말을 그 표기로 바꾼다. |
| 근거 연결 | 채운 칸마다 근거 발언(시각)을 연결한다. |
| 양식 저장·출력 | 확인한 칸 구성을 "발주처·용역명"으로 저장한다(4-5). 결과는 hwpx(한글 2014 이후). |

### 3-6. ④ 검토의견 반영

| 기능 | 처리 |
|---|---|
| 수정 요청 목록 | ③ 보고서의 의견 행(위치, 검토위원 의견, 발주처 의견, 반영 방향, 근거 발언)을 가져온다. ③이 없으면 녹취록에서 뽑는다. 서로 부딪치는 요청은 "의견 엇갈림"으로 표시한다. |
| 고친 안 | 반영할 요청마다 해당 항목의 고친 안을 만들고, 자료·DB 참고 문서에서 같은 기법의 다른 과제·가이드를 찾아 근거를 붙인다. 함께 바꿔야 할 다른 항목(가이드 포함)을 알린다. |
| 출력 | pptx, 반영 내역표(요청 → 반영 여부 → 고친 위치). |
| 검토 교훈 | 다른 과제에도 쓸 만한 교훈을 정리해, 관리자가 정한 교훈 파일(4-2. 현재: `isomorph-ac`의 `references/review-lessons.md`)에 넣자는 제안을 제안 대기로 보낸다. |

## 4. 관리자 기능

### 4-1. 메뉴

지침 관리, 점검 항목 관리, 자료·DB 관리, 양식·구조 관리, 설정. 관리자 계정에만 보이고 서버에서도 권한을 확인한다.

### 4-2. 지침 관리

| 기능 | 처리 |
|---|---|
| 기능별 지침 | 기능마다 스킬 / 직접 쓴 지침을 고르고 연결한다. 현재 연결: ① `ac-topic-storymap`(스킬), ② `isomorph-ac`(스킬), ③ 녹취록 요약·양식 칸 채우기(직접 쓴 지침), ④ 수정 요청 반영(직접 쓴 지침), 그림·지도·차트 `ac-figure`(스킬, 저장소 `skills/ac-figure/`). |
| 포털이 읽는 것 | 지침마다 "이 지침을 바꾸면 달라지는 이용자 화면"을 보여 준다: 확인 단계 목록(★정지), 받는 결과 틀, 관련 설정. |
| 화면 표시 이름 | ★정지 단계와 스킬 용어마다 이용자 화면에 보일 이름을 정한다. 정하지 않으면 스킬의 제목을 보인다. |
| 보내는 곳 | 다른 지침으로 보내는 연결을 정한다. 현재: ④ 검토 교훈 → `isomorph-ac`의 `references/review-lessons.md`. |
| 스킬 불러오기 | 스킬 폴더 zip을 올리면: SKILL.md 본문 → 그 기능의 시스템 프롬프트, references/ → 지침이 언급할 때 함께 넣는 문서, examples/ → 작성 예시와 시험 실행 입력, scripts/ → 서버의 격리된 실행 환경에서 실행. 모델에는 웹 검색, 파일 읽기·쓰기, 코드 실행 도구를 제공한다(도구 호출 지원 모델 필요). |
| 고치기 | SKILL.md, references/, examples/는 화면에서 고친다. scripts/는 보기만 한다(고치기는 개발 담당). AI에게 고쳐 달라고 할 수도 있다. |
| 저장 전 자동 점검 | name이 그대로인지 / description이 비어 있지 않은지 / SKILL.md 본문 500줄 이하 / 300줄 넘는 references/ 문서에 목차 / SKILL.md가 가리키는 경로가 실제로 있는지 / "반드시·절대" 같은 강한 말 개수(경고만). 통과하지 못하면 이유를 보이고 그래도 저장할지 묻는다. AI가 고칠 때도 같은 규칙을 지키게 한다. |
| 시험 실행 | 예시 파일로 지금 버전과 고친 버전의 결과를 나란히 보여 준다. 고친 버전의 결과가 결과 틀의 필수 칸을 채우는지, 확인 단계가 늘거나 줄었는지도 보여 준다. |
| 적용 범위 | 저장할 때 "새 과제부터" / "진행 중인 과제에도(다음 단계부터)"를 고른다(2-2). |
| 수정 기록 | 저장마다 버전, 날짜, 고친 사람, 바꾼 이유, 적용 범위. 직전 수정을 되돌린다. |
| 제안 대기 | 다른 기능에서 온 스킬 수정 제안(④ 검토 교훈)을 모아 [반영] / [반영 안 함]. |
| ★정지 연동 | SKILL.md의 ★정지 표시를 찾아 이용자 화면의 확인 단계로 만든다. 넣거나 빼면 확인 단계도 바뀐다. |

### 4-4. 자료·DB 관리

| 탭 | 칸 | 쓰는 곳 |
|---|---|---|
| 기출 DB | 연도, 발주처, 직급, 기법, 해결과제명·측정 역량, 서버 파일명 | ① 조건 목록, 평가 조건, 구조 분석, 겹침 판단 |
| 발주처 주제풀 | 발주처, 직급, 연도, 주제, 선정 여부, 서버 파일명 | ① 조건 목록, 겹침 판단 |
| 실무 DB | 발주처, 연도, 부서, 담당 업무 | ① 겹침 판단 |
| 역량 정의 | 기관, 직급, 역량, 하위요소 | ① 측정 역량, 역량-내용 연계 분석 |
| 참고 문서 | 평가과제, 평가자가이드, 기관 자료 파일 | ②④ 참고 검색 |
| 용역 설정 | 평가 조건, 구조 분석 결과, 확정 주제, DB 기준 정보 | ① 결과 재사용 |

- 행 추가·고치기·지우기, CSV 가져오기·내보내기.
- 서버 파일명으로 파일을 찾아 검색 색인(RAG)을 만든다. 서버에 없는 파일은 "서버에 파일 없음"으로 표시한다. [색인 다시 만들기]로 DB 기준 정보가 바뀌면 ①에서 구조 분석을 다시 한다.

### 4-5. 양식·구조 관리

| 대상 | 저장하는 것 | 쓰는 곳 |
|---|---|---|
| 보고서 양식 | 발주처·용역명, hwpx 원본, 칸 구성 | ③ 저장된 양식 고르기 |
| 과제 파일 목차 규칙 | 용역, 방향·쪽 크기, 자료 표기, 구분 규칙 | ②④⑤ pptx 나누기 |
| 지도 범례 항목 | 항목마다 이름, 종류(지점·선·면), 색, 사용 여부. 항목 추가 가능 | 지도 편집기, AI 지도 초안(끈 항목은 빠짐) |
| 차트 | 계열 색 4개, 글꼴 | 차트 미리보기, PPT 차트 |
| 그림 기본값 | 느낌, 비율, 자료당 그림·지도·차트 상한(기본 2개, 이미 있는 것 포함) | 그림 만들기, AI 자리 제안 |

- 그림·지도·차트 양식은 바로 저장되고 새로 만드는 것부터 적용된다. 이미 넣은 것은 다시 만들어야 바뀐다.

### 4-6. 설정

| 설정 | 끄면 |
|---|---|
| 웹 검색 | ① 시의성 확인, ④ 참고 조사를 사내 자료로만 한다. |
| 그림 만들기 | 이미지 생성을 쓰지 않는다. 그림은 파일로 올린다. 지도·차트는 그대로 쓴다. |
| AI 자리 제안 | 자리 제안 버튼이 사라진다. |
| 이용자 권한 | 사람마다 이용자 / 관리자를 정한다. |

- 시안 설정의 "시안 체험: 진행 중 실패 화면 보기"는 시안 확인용이므로 만들지 않는다.
