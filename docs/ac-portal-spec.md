## 2. 작업 원칙 (모든 화면에 공통 적용)

1. **화면에는 고를 것만 둔다.** 모델 선택, 프롬프트 작성, 온도·토큰 설정은 이용자 화면에 두지 않는다. 그런 설정은 관리자 화면에서만 다룬다.
2. **일정한 점검은 버튼으로, 그때그때 필요한 요청은 채팅으로 한다.** 매번 같은 기준으로 하는 점검은 관리자가 버튼으로 등록하고, 이용자는 누르기만 한다. 그 밖의 추가 점검이나 수정 요청은 채팅으로 받는다.
3. **AI가 지적하거나 고친 내용은 모두 문서 위 위치와 함께 보여 준다.** "어디가, 왜, 어떻게 고치면 되는지"를 한 묶음으로 보여 주고, 반영 여부는 이용자가 정한다.
4. **바뀐 내용은 언제든 되돌릴 수 있다.** AI가 고친 것이든 이용자가 고친 것이든 모두 버전으로 남기고, 이전 버전과 비교하거나 되돌릴 수 있다.
5. **숫자 계산은 프로그램이 한다.** AI는 "어느 숫자끼리 맞아야 하는지"만 찾는다. 합계, 비율, 날짜·요일 같은 계산은 서버의 계산 코드가 맡는다.
6. **지침은 한곳에서 관리한다.** 기능마다 쓰는 지침(스킬 또는 지침 프롬프트)과 점검 항목은 관리자 화면 한곳에서 고치고, 고친 내용은 모든 이용자에게 바로 적용된다.
7. **한 곳을 고치면 영향을 받는 곳을 함께 보여 준다.** 과제의 숫자나 자료를 고치면 같은 사실을 쓰는 다른 자료와 평가자가이드의 해당 부분을 표시한다.
8. **양식과 파일 구조는 고정하지 않는다.** 용역마다 다른 양식과 과제 파일을 AI가 먼저 읽고 구조를 제안하며, 이용자는 확인만 한다. 확인한 구조는 저장해서 다시 쓴다.

## 3. 지침 관리 방식: 스킬 불러오기 + 지침 프롬프트

### 3-1. 기본 방식: 기존 스킬을 그대로 불러온다

기존 스킬 폴더(`SKILL.md` + `references/` + `scripts/`)를 관리자가 zip으로 올리면 포털이 다음처럼 나눠 쓴다.

| 스킬 구성 | 포털에서 쓰는 방법 |
|---|---|
| `SKILL.md` 본문 | 해당 기능의 지침 프롬프트(시스템 프롬프트)로 넣는다. |
| `references/` 문서 | 참고자료 저장소에 넣고, 지침이 그 문서를 언급할 때 찾아서 함께 넣는다. |
| `scripts/` 코드 | 서버의 격리된 실행 환경에서 돌린다. 예: pptx 읽기·쓰기, 표 계산 |
| `SKILL.md` 머리말(name, description) | 기능 선택 화면의 이름과 설명으로 쓴다. |

**미리 알아 둘 제약**
- 기존 스킬은 Claude가 웹 검색, 파일 생성, 코드 실행 도구를 쓴다고 가정하고 쓰여 있다. 오픈소스 모델에서 같은 결과를 내려면 포털이 같은 도구(웹 검색, 파일 읽기·쓰기, 코드 실행)를 모델에 제공해야 하고, 모델은 도구 호출(function calling)을 지원해야 한다.
- 도구를 제공하지 못하는 단계는 아래 3-2 방식으로 대신한다.

### 3-2. 대체 방식: 지침 프롬프트를 관리자가 직접 쓴다

스킬을 그대로 돌리기 어려운 기능, 또는 해당 스킬이 없는 기능은 관리자가 지침 프롬프트를 직접 입력한다.

### 3-3. 관리자 화면에서 지침을 다루는 규칙

- 기능마다 "스킬 불러오기" 또는 "지침 프롬프트 직접 쓰기" 중 하나를 고른다.
- 지침을 고칠 때마다 버전이 남는다(고친 사람, 날짜, 바뀐 줄). 이전 버전으로 되돌릴 수 있다.
- 저장하기 전에 예시 파일로 시험 실행을 해 볼 수 있다.

### 3-4. 기능별 지침 연결

| 기능 | 연결할 지침 | 방식 |
|---|---|---|
| ① 주제 탐색 | `ac-topic-storymap` | 스킬 불러오기 |
| ② 과제 초안(평가과제 + 평가자가이드) | `isomorph-ac` | 스킬 불러오기 |
| ③ 검토회의 보고서 | (스킬 없음) 녹취록 요약·양식 칸 채우기 지침 | 지침 프롬프트 직접 쓰기 |
| ④ 검토의견 반영 | (스킬 없음) 수정 요청 반영 지침. 필요하면 `isomorph-ac` 일부를 참조한다. | 지침 프롬프트 직접 쓰기 |
| ⑤ 검수 | 점검 항목(4장)을 그대로 사용 | 점검 버튼 |

## 4. 점검 항목 관리 (현실적합성, 오탈자 등)

### 4-1. 구조

관리자가 점검 항목을 등록하면, 이용자의 편집 화면 위쪽에 버튼으로 나타난다.

| 등록 칸 | 설명 | 예시 |
|---|---|---|
| 이름 | 버튼에 보일 이름 | 현실적합성 점검 |
| 지침 프롬프트 | 무엇을 어떤 기준으로 찾을지 적는다. | 실제 있는 법령·제도인가, 그 직급에 그 권한이 있는가, 예산·인원 규모가 현실적인가, 날짜와 요일이 맞는가 |
| 계산 코드 사용 | 숫자 계산이 필요한 항목이면 켠다. | 수치 점검에서 켬 |
| 표시 색 | 문서 위에 표시할 색 | 주황 |
| 보이는 기능 | 어느 단계 화면에 버튼을 보일지 정한다. | ②, ④, ⑤ |
| 순서·사용 여부 | 버튼 순서, 숨김 여부 | |

### 4-2. 처음에 넣어 둘 점검 항목 (관리자가 고치거나 지울 수 있음)

| 이름 | 찾는 것 | 계산 코드 |
|---|---|---|
| 현실적합성 | 실제와 맞지 않는 제도·권한·규모·일정 | 날짜·요일만 사용 |
| 오탈자 | 맞춤법, 띄어쓰기, 오타, 기관명·인물명 표기 불일치 | 사용 안 함 |
| 수치 계산 | 예산 합계, 비율, 증감률, 인원 합계가 맞는지. 표와 차트 안의 숫자도 포함한다. | 사용 |
| 자료 간 일치 | 같은 사실(금액, 날짜, 인물, 직위)이 자료마다 다르게 적혔는지, 자료끼리 조건이 충돌하는지 | 사용 |
| 근거 없는 내용 | 다른 자료에 근거가 없는 주장이나 결론 | 사용 안 함 |
| 표현 | 뜻이 모호한 용어, 응시자에게 정답을 알려 주는 표현, 차별적 표현 | 사용 안 함 |
| 구성 점검 | 자료 번호가 빠지거나 겹치는지, 표지의 "총 n장" 안내와 실제 장수가 맞는지, 쪽 번호가 이어지는지 | 사용 |
| 과제-가이드 일치 | 가이드가 정답 근거로 든 자료·수치가 과제에 실제로 있는지, 과제의 숫자와 가이드의 계산 답이 맞는지 | 사용 |

### 4-3. 점검 결과를 보여 주는 방식

- 문서 위 해당 글자에 점검 항목 색으로 밑줄을 긋는다.
- 오른쪽에 결과 카드를 띄운다. 카드에는 **점검 항목 / 위치(예: 자료3, 2번째 표) / 문제 / 고친 안 / [반영] [무시]** 버튼이 들어간다.
- [반영]을 누르면 고친 안이 문서에 들어가고 새 버전이 남는다.
- 추가 점검이나 다른 수정은 채팅으로 요청한다. 예: "자료 2와 자료 5의 예산이 왜 다른지 다시 봐 줘"

## 5. 공통 편집 화면 (②, ④, ⑤가 같이 씀)

### 5-1. 배치

```
┌──────────────┬──────────────────────────────┬────────────────────┐
│ 블록 목록     │ 문서 본문                     │ 채팅 / 점검 / 버전  │
│ 평가과제      │ [점검 버튼: 현실적합성 오탈자 …] │ 수정 범위: 자료 2   │
│  구조         │                              │ ─────────────────  │
│  공통 자료    │  (선택한 블록 내용)            │ 결과 카드 …         │
│  역할별 자료  │                              │                    │
│ 평가자가이드  │  [바뀐 부분 보기]              │ [고칠 내용 입력]    │
└──────────────┴──────────────────────────────┴────────────────────┘
```

- 휴대폰 폭에서는 세 영역을 탭(목록 / 문서 / 채팅)으로 바꿔 보여 준다.

### 5-2. 수정 방법 3가지

| 방법 | 동작 | 채팅에 걸리는 범위 |
|---|---|---|
| 블록 클릭 | 왼쪽 목록에서 "자료 2"를 누른다. | 채팅창 위에 "수정 범위: 자료 2"가 표시되고, 요청은 자료 2에만 적용된다. |
| 드래그 선택 | 본문에서 글자를 드래그하면 작은 메뉴가 뜬다: [AI에게 고쳐 달라고 하기] [직접 고치기] | 드래그한 글자에만 적용된다. |
| 전체 요청 | 범위를 지정하지 않고 채팅에 쓴다. | 문서 전체. AI가 어느 블록을 고쳤는지 함께 알려 준다. |

### 5-3. 바뀐 부분 확인

- **바뀐 부분 보기**를 켜면 이전 버전과 비교해 지운 글자는 빨간 취소선, 넣은 글자는 초록 바탕으로 보인다.
- 왼쪽 블록 목록에서 바뀐 블록 옆에 점을 찍는다.
- **버전 기록**에는 버전마다 "누가(이용자/AI), 무엇 때문에(채팅 요청 문장, 점검 항목 이름), 어느 블록을" 고쳤는지 한 줄로 남는다. 아무 버전이나 골라 되돌릴 수 있다.
- 고친 블록과 같은 사실을 쓰는 다른 블록(평가자가이드 포함)에는 "함께 확인 필요" 표시를 붙인다(작업 원칙 7).

### 5-4. pptx를 블록으로 나누는 규칙 (샘플 집단토론 과제 기준)

샘플 파일을 읽어 확인한 구조와 그에 맞춘 규칙이다.

| 샘플에서 확인한 사실 | 규칙 |
|---|---|
| 슬라이드의 제목 칸에는 쪽 번호("- 6 -")만 있고, "자료 3. ○○ 현황(1/4)" 같은 제목은 일반 글상자에 있다. | 제목 칸이 아니라 모든 글상자에서 `자료 N.` 형식의 글을 찾아 자료를 나눈다. |
| "자료 3"이 "(1/4)~(4/4)"로 4장에 걸쳐 있다. | 같은 자료 번호의 연속 슬라이드는 한 블록으로 묶고, 블록 안에서 장을 나눠 보여 준다. |
| "평가대상자A 역할별 자료 / ○○과 / ○○○ 과장" 같은 간지 슬라이드가 3번 나온다. | 간지가 나오면 그 뒤 자료를 해당 역할 묶음에 넣는다. 간지가 없으면 "공통 자료"로 둔다. |
| 표지, 평가방법 안내, 상황개요, 가상조직, 마침 슬라이드에는 자료 번호가 없다. | 자료 번호가 없는 슬라이드는 "구조" 묶음의 블록으로 둔다. |
| 간지는 쪽 번호가 없지만 쪽 수에 포함된다. 검토회의 양식은 위치를 "6page"처럼 인쇄 쪽으로 적는다. | 위치 표기는 슬라이드 순번이 아니라 인쇄된 쪽 번호를 쓴다. |
| 상황개요, 가상조직 슬라이드의 글이 그룹 도형 안에 있다. | 그룹 도형 안의 글상자까지 읽는다. |
| 슬라이드 3장에 차트 4개, 여러 장에 그림이 있다. | 차트 안의 숫자는 읽어서 수치 점검에 쓴다. 차트와 그림은 AI가 고치지 않고 "직접 고쳐야 할 곳"으로 표시한다. |

샘플을 이 규칙으로 나눈 결과:

| 묶음 | 블록 (인쇄 쪽) |
|---|---|
| 구조 | 표지, 평가방법 안내(1), 상황개요(2), 가상조직(3), 마침 |
| 공통 자료 | 자료 1(4), 자료 2(5), 자료 3(6~9, 4장) |
| 평가대상자 A | 자료 5(11), 자료 6(12) |
| 평가대상자 B | 자료 7(14), 자료 8(15) |
| 평가대상자 C | 자료 9(17), 자료 10(18) |

- 이 규칙으로 나누다가 **자료 4가 없는 것**(자료 3 다음이 자료 5)을 찾았다. 의도한 것인지 확인이 필요하다(9장). 이런 경우는 "구성 점검" 항목에서 자동으로 알려 준다.
- 표지의 "총 19장(표지 제외)" 안내는 실제 장수(20장 − 표지 1장)와 맞았다.
- 자동으로 나눈 결과가 틀리면 이용자가 블록 목록에서 끌어서 고친다. 고친 규칙은 같은 용역의 다음 파일에 다시 쓴다.

### 5-5. 파일 형식

- ②에서 만든 평가과제는 pptx, 평가자가이드는 pptx 또는 docx(참조 가이드와 같은 형식)로 내보낸다.
- ④와 ⑤는 pptx를 불러와 5-4 규칙으로 나눈 뒤 같은 편집 화면에 보여 준다.
- pptx를 고칠 때는 글자만 바꾸고 레이아웃, 글꼴, 표 모양은 그대로 둔다.

### ③ 검토회의 결과보고서

**3-1. 녹취록 만들기 (클로바노트와 같은 방식)**

| 순서 | 동작 |
|---|---|
| 1 | 음성 파일(mp3, m4a, wav)을 올린다. 참석 인원(3~5명)을 고른다. 모르면 "자동"으로 둔다. |
| 2 | 서버가 음성을 글로 바꾸고 화자를 나눈다. 결과는 `Speaker 1` ~ `Speaker 5`, 발언 시각, 발언 내용으로 나온다. |
| 3 | 화자 정보 고치기: `Speaker 1`을 누르고 이름("김○○"), 소속("○○대학교 교수"), 구분(검토위원 / 발주처 / 개발사)을 적으면 그 화자의 모든 발언에 한 번에 적용된다. 구분은 양식의 참석인원 칸과 "검토위원 의견" 열을 채우는 데 쓴다. |
| 4 | 발언 줄을 누르면 그 시각부터 음성이 재생된다. 잘못 들린 글자를 그 자리에서 고칠 수 있다. |
| 5 | 화자가 잘못 나뉜 줄은 화자 이름을 눌러 다른 화자로 바꾼다. |

**3-2. 양식 채우기 (양식이 용역마다 달라도 됨)**

| 순서 | 동작 |
|---|---|
| 1 | 양식을 고른다. 같은 용역에서 쓴 적이 있으면 저장된 양식을 고르기만 한다. 없으면 hwp 또는 hwpx 파일을 올린다. |
| 2 | AI가 양식을 읽고 채울 칸을 찾아 제안한다(아래 표). 이용자는 칸마다 [AI가 채움] / [비워 둠] / [직접 입력] 중 하나만 확인한다. |
| 3 | 이전 회차 내용이 들어 있는 양식을 올리면, 그 내용을 문체와 표기 방식의 예시로 쓴다. 예: 문장 끝 "~하겠음", 위치 표기 "[자료3. 제목(2/3), 6page]" |
| 4 | 평가과제 pptx(②나 ④의 파일)를 함께 고르면, 회의에서 "자료 3 두 번째 장"이라고 말한 것을 양식의 위치 표기 방식(자료 제목, 장 번호, 인쇄 쪽)으로 바꿔 적는다. |
| 5 | AI가 칸을 채운 미리보기를 보여 준다. 칸마다 근거가 된 발언으로 이동할 수 있다. 직접 고치거나 채팅으로 고친다. 예: "의견을 위원별로 나눠 줘" |
| 6 | [hwpx로 받기]. 확인한 칸 구성은 "발주처·용역명" 이름으로 저장되어 같은 용역의 2차, 3차 회의에 다시 쓴다. |

**샘플 양식에서 AI가 찾아야 할 칸 (제안 예시)**

| 양식의 칸 | 채우는 방법 |
|---|---|
| 제목줄(연도, 기관, 직급, 기법, 기수·차수) | 프로젝트 정보로 채움 |
| 건명, 일시 | 프로젝트 정보 + 녹음 파일 날짜로 채움 |
| 참석인원(총 n명, 구분별 소속·이름) | 3-1에서 고친 화자 정보로 채움 |
| 회의내용 표: 위치 행 | 의견이 가리키는 자료의 위치 표기. 첫 행은 "과제 전반" |
| 회의내용 표: "검토위원 의견" 열 | 검토위원 구분 화자의 발언을 요약 |
| 회의내용 표: "발주처 의견" 열 | 샘플에서는 비어 있음. 기본값 [비워 둠] (9장 확인 필요) |
| 회의내용 표: "개선 및 반영 방향" 열 | 개발사 화자의 답변과 회의 결론을 "~하겠음" 문체로 요약 |
| 향후일정 표 | 회의에서 나온 다음 일정. 없으면 [직접 입력] |

- 회의내용 표는 "위치 행 1줄 + 내용 행 1줄"이 한 묶음으로 반복된다. AI는 이 반복 묶음을 찾아 의견 수만큼 복사한다.

**hwp 파일 처리**
- 읽기: hwp(한글 5.0 형식)는 서버에서 읽을 수 있다. 샘플 양식의 글자와 표 구조를 실제로 읽어 확인했다.
- 쓰기: 채운 결과를 hwp로 직접 쓰는 오픈소스 도구는 믿고 쓸 만한 것이 없다. 결과는 hwpx로 내보낸다(한글 2014 이후 버전에서 열림).
- hwp 양식을 hwpx로 바꾸는 방법은 두 가지다(9장에서 선택).
  - 방법 A: 양식을 처음 등록할 때 한글에서 "다른 이름으로 저장 → hwpx"로 한 번 바꿔 올린다. 양식은 용역별로 한 번만 등록하므로 부담이 적다.
  - 방법 B: 한컴 문서 변환 엔진(유료)을 서버에 설치해 자동으로 바꾼다.

### ④ 검토의견 반영

| 순서 | 동작 |
|---|---|
| 1 | 수정할 평가과제 pptx를 고른다. ②에서 만든 것이 있으면 자동으로 선택된다. 평가자가이드도 함께 불러온다. |
| 2 | **수정 요청 목록**은 ③ 보고서 표의 의견 행을 그대로 가져온다. 항목마다 위치, 검토위원 의견, 반영 방향, 근거 발언(시각)이 들어간다. ③을 거치지 않았다면 녹취록에서 새로 뽑는다. |
| 3 | 이용자가 반영할 항목에 체크한다. 서로 부딪치는 요청(예: 위원 A는 늘리자, 위원 B는 줄이자)은 따로 표시한다. |
| 4 | AI가 체크된 항목별로 고친 안을 만든다. 이때 참고자료 저장소의 다른 평가과제와 평가자가이드를 찾아 근거로 붙인다. 예: "2024년 ○○과제 자료 4의 구성을 참고함" |
| 5 | 공통 편집 화면에서 고친 안을 하나씩 [반영] / [무시]한다. 바뀐 부분 보기로 확인한다. 과제를 고쳐 영향을 받는 가이드 부분에는 "함께 확인 필요"가 붙는다. |
| 6 | [pptx로 받기]. [반영 내역표 받기]를 누르면 "요청 → 반영 여부 → 고친 위치"를 표로 받는다. |

### ⑤ 검수

| 구분 | 내용 |
|---|---|
| 넣는 것 | 완성된 평가과제 pptx와 평가자가이드(④ 결과가 있으면 자동 선택) |
| 화면 | 공통 편집 화면 + 점검 버튼 줄. [전체 점검]을 누르면 등록된 점검 항목을 모두 돌린다. |
| 결과 | 점검 항목별 개수 요약(예: 오탈자 7, 수치 계산 2, 구성 1) + 문서 위 표시 + 결과 카드 |
| 동작 | 카드마다 [반영] / [무시]. 추가 점검은 채팅으로 한다. |
| 나오는 것 | 고친 pptx, 검수 결과표(엑셀) |
