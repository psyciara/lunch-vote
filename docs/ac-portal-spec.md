## 1. 개요

사내 서버에 설치한 오픈소스 AI 모델로 역량평가 과제 개발을 돕는 사내 포털이다. 과제 1건을 다섯 단계로 처리한다.

| 단계 | 넣는 것 | 나오는 것 |
|---|---|---|
| ① 주제 탐색 | 발주처, 직급, 평가 기법 | 해결과제명·측정 역량, 스토리맵 |
| ② 과제 초안 | 스토리맵, 참조 평가과제, 참조 평가자가이드 | 평가과제·평가자가이드 초안 |
| ③ 검토회의 보고서 | 회의 녹음 파일, 보고서 양식(hwpx) | 검토회의 결과보고서(hwpx) |
| ④ 검토의견 반영 | 평가과제 pptx, 검토회의 보고서 | 의견을 반영한 평가과제 |
| ⑤ 검수 | 평가과제 pptx, 평가자가이드 | 고친 pptx, 검수 결과표 |

### 1-1. 이용자 구분

| 구분 | 누구 | 쓰는 화면 |
|---|---|---|
| 이용자 | 과제 개발 담당자(연구원·컨설턴트) | 시작 화면, ①~⑤ 단계 화면(3장) |
| 관리자 | 담당자 가운데 일부. 이용자 화면도 그대로 쓴다. | 이용자 화면 + 관리자 화면(4장). 관리자 화면 버튼은 관리자 계정에만 보인다. |

### 1-2. 전제 조건

| 항목 | 내용 |
|---|---|
| 처리 위치 | 모든 처리(언어 모델, 이미지 생성, 음성 인식, 화자 구분, 파일 변환)는 사내 서버 안에서만 한다. 외부 AI API는 쓰지 않는다. |
| 사용 환경 | 주로 사무실 PC. 휴대폰은 확인용으로 쓰며, 모든 화면은 휴대폰 폭에서도 깨지지 않는다. |
| 작업 단위 | 과제 1건 = 프로젝트 1개. 다섯 단계의 결과물은 프로젝트 안에 쌓이고, 앞 단계 결과를 다음 단계가 그대로 받아 쓴다. |
| 인터넷 | 웹 검색은 관리자가 켜고 끈다. 꺼져 있으면 사내 자료만 쓴다. |

### 1-3. 함께 보내는 것

| 파일 | 내용 |

## 2. 공통 원칙

### 2-1. 처리 원칙

1. **이용자 화면에는 고를 것만 둔다.** 모델 선택, 프롬프트, 온도·토큰 같은 설정은 관리자 화면에서만 다룬다.
2. **일정한 점검은 버튼으로, 그때그때 필요한 요청은 채팅으로 한다.** 같은 기준으로 반복하는 점검은 관리자가 점검 항목으로 등록하고, 이용자는 누르기만 한다.
3. **AI는 제안하고 사람이 정한다.** AI가 지적하거나 고친 내용은 문서 위 위치와 바뀌는 부분(지운 글자·넣은 글자)을 먼저 보여 주고, 이용자가 [반영] / [다른 안 제안받기] / [반영 안 함] 가운데 하나를 고른다.
4. **바뀐 내용은 언제든 되돌릴 수 있다.** AI가 고친 것이든 이용자가 고친 것이든 수정 기록으로 남고, 이전 버전과 비교하거나 되돌릴 수 있다.
5. **숫자 계산은 프로그램이 한다.** AI는 어느 숫자끼리 맞아야 하는지만 찾고, 합계·비율·날짜·요일 계산은 서버의 계산 코드가 맡는다.
6. **지침은 한곳에서 관리한다.** 기능별 지침(스킬 또는 직접 쓴 지침)과 점검 항목은 관리자 화면에서 고치며, 고친 내용은 모든 이용자에게 바로 적용된다.
7. **한 곳을 고치면 영향받는 곳을 함께 알린다.** 과제의 숫자나 자료를 고치면 같은 내용을 쓰는 다른 자료와 평가자가이드 부분에 "함께 확인 필요"를 붙인다.
8. **양식과 파일 구조를 고정하지 않는다.** 보고서 양식, 과제 파일의 방향(가로·세로), 쪽 크기, 자료 개수, 자료 표기 방식은 용역마다 다르다. AI가 먼저 구조를 제안하고 이용자가 확인하며, 확인한 구조는 용역별로 저장해 다시 쓴다.

### 2-2. 화면 원칙

| 번호 | 원칙 | 적용 방법 |
|---|---|---|
| 1 | 첫 화면에서 전체 순서를 보여 준다. | 시작 화면(3-1)에 다섯 단계를 "넣는 것 → 나오는 것"으로 보여 주고, 어느 단계부터든 시작할 수 있게 한다. |
| 2 | 단계마다 같은 틀을 쓴다. | 위: 화면 제목과 "무엇을 결정하는지" 한 줄. 가운데: 결정할 것. 아래: [이전 단계], 그 단계를 마친 뒤에만 [다음 단계]. "이 단계에서 할 일" 안내는 머리의 [도움말]로 연다. |
| 3 | 지금 위치가 항상 보인다. | 단계 표시줄에 단계마다 "완료 / 진행 중 / 시작 전"을 글자로 적는다. 단계 안의 세부 단계는 "단계 3 / 7" 한 줄과 진행 막대로 보여 준다. |
| 4 | 결정에 필요한 것만 바로 보인다. | 스킬·지침에 따라 바뀌는 세부 내용은 접힌 "자세히 보기"에 두거나 관리자 화면에만 둔다(2-4). |
| 5 | 파란 버튼은 한 화면에 하나다. | 나머지는 테두리 버튼이다. 아래쪽 [다음 단계], 안내 닫기, 채팅 [보내기]도 테두리 버튼이다. 결과 카드의 [반영]은 펼친 카드에서만 파란색이다. |
| 6 | 누를 수 없는 버튼은 이유를 옆에 적는다. | 예: "파일 3개 중 2개를 올렸습니다. 참조할 평가자가이드를 올려 주세요." |
| 7 | 빈 화면에는 할 일과 버튼을 둔다. | 예: "아직 점검하지 않았습니다" + [전체 점검] |
| 8 | 오래 걸리는 작업은 진행 단계와 예상 시간을 보여 준다. | 예: "음성을 글로 바꾸기 → 화자 나누기 (1시간 녹음 기준 약 5분)" |
| 9 | 실패하면 그 자리에서 알리고 다시 할 길을 준다. | 무엇이 실패했는지, 짐작되는 이유, [다시 시도] / [이전 화면으로]를 진행 화면 자리에 보여 준다. 이미 한 작업은 지우지 않는다. |
| 10 | AI 수정 요청 상자는 어디서나 같은 모양이다. | 결과 아래에 [AI에게 고쳐 달라고 하기] 버튼 하나를 두고, 누르면 예시 요청 2개와 입력창이 펼쳐진다. 반영한 뒤에도 [되돌리기]를 할 수 있다(3-9). |
| 11 | 되돌릴 수 없는 동작만 한 번 더 묻는다. | 지우기는 "정말 지울까요?"를 묻는다. 반영처럼 되돌릴 수 있는 동작은 묻지 않고, 반영 직후 알림에 [되돌리기]를 둔다. |
| 12 | 아이콘은 선 아이콘을 글자와 함께 쓴다. 색만으로 뜻을 전하지 않는다. | 점검 항목은 색 + 이름, 상태는 아이콘 + 글자 |
| 13 | 글자와 누르는 곳을 충분히 크게 한다. | 본문 15px 이상, 보조 글 13px 이상, 글자 대비 4.5:1 이상, 버튼 높이 36px 이상(휴대폰 44px 이상) |
| 14 | 키보드로도 쓸 수 있다. | Tab 이동과 포커스 테두리, Esc로 작은 창 닫기. 화면을 다시 그려도 포커스를 지키고, 화면이 바뀌면 제목으로 옮긴다. 진행 상황은 화면 읽기 프로그램에 알린다. 드래그 대신 [이 항목 고쳐 달라고 하기]를 쓸 수 있다. 오른쪽 칸 탭은 화살표 키로 옮긴다. |
| 15 | 편집 화면을 처음 열면 사용법 3가지를 보여 준다. | 목차에서 항목 고르기 / 드래그 또는 [이 항목 고쳐 달라고 하기] / [전체 점검] 뒤 [하나씩 검토]. 닫으면 다시 뜨지 않는다. |
| 16 | 필요 없는 선택지는 보이지 않는다. | 관리자 화면 버튼은 관리자 계정에만 보인다. |
| 17 | 주소만으로 화면을 열 수 있다. | 단계와 관리자 메뉴가 주소에 남는다(예: `#step-3`, `#admin-checks`). |
| 18 | 저장되지 않은 수정이 있으면 창을 닫기 전에 묻는다. | 실제 서비스는 자동 저장하고, 저장 전이면 브라우저 확인 창을 띄운다. |

## 3. 이용자 기능

### 3-1. 시작 화면

| 구분 | 내용 |
|---|---|
| 보여 주는 것 | 진행 중인 과제 목록(과제 이름, 현재 단계, 마지막 수정일), [새 과제 시작], 다섯 단계 카드 |
| 단계 카드 | 단계 이름, 넣는 것, 나오는 것, [이 단계부터 시작]. 예: 스토리맵이 이미 있으면 ②부터 시작한다. |

### 3-2. ① 주제 탐색 (ac-topic-storymap 스킬의 진행 절차)

스킬은 단계 끝마다 사용자 확인을 받고 넘어간다. 화면도 같은 순서로 나눈다.

| 화면 단계 | 이용자가 하는 일 |
|---|---|
| 1. 조건 입력 | 발주처·직급(드롭다운, 필수), 평가 기법(필수)을 고른다. 발주처·직급 목록은 자료·DB(4-4)에서 만들어지며, 직급 목록은 고른 발주처에 맞춰 바뀐다. |
| 2. 평가 조건 확인 | 기출에서 찾은 해결과제 수와 해결과제별 측정 역량, 업무 관련성, 가상조직 기관 유형을 확인한다. 필요하면 [조건 고치기]로 바꾼다. 스킬이 사용자에게 묻도록 정한 질문(예: 주제풀에서 채택되지 않은 제안 주제도 피할지)에 답해야 넘어간다. 질문에는 추천값과 이유를 붙인다. 근거(파일명, 근거 표시 [DB 확인] / [설정 문서] / [추론] / [확인 불가])는 [근거 보기]에 있다. 같은 조합의 기출이 없으면 조건을 직접 정하라고 알린다. |
| 3. 기출 구조 분석 확인 | 과제 단위, 대립 구조, 규모 요약을 확인한다. 확인하면 용역 설정 문서에 저장한다. 용역 설정 문서의 DB 기준 정보가 지금 DB와 같으면 이 단계는 건너뛴다. |
| 4. 해결과제 1 고르기 | 서로 다른 분야의 후보 5개 가운데 하나를 골라 고정하거나 고쳐서 고정한다. 후보마다 해결과제명, 측정 역량, 내용, 기출과 겹침 여부가 보인다. 기출과 겹칠 수 있는 후보는 접힌 묶음에 두며, 고정하려 하면 가까운 기출을 보여 주고 "그래도 고정할까요?"를 묻는다. |
| 5. 해결과제 2…n 고르기 | 고정한 가상조직이 맡을 만한 다른 업무로 후보 5개가 나온다. 해결과제 수만큼 반복한다. |
| 6. 전체 확정 | 발주처, 가상조직, 해결과제 목록(해결과제명, 측정 역량)을 보고 [스토리맵 쓰기]를 누른다. 승인 전에는 스토리맵을 쓰지 않는다. |
| 7. 스토리맵 | 형식 기준 스토리맵을 따른 스토리맵을 확인한다. 역량-내용 연계 분석 표(내부 검토용)는 접혀 있다. [과제 초안 만들기]로 넘긴다. |

- 근거 파일명을 누르면 서버의 그 파일에서 찾은 부분과 파일 위치를 보여 준다(4-4).
- 고정한 해결과제명과 측정 역량은 화면 위쪽 프로젝트 이름 자리에 계속 보인다.

### 3-3. ② 과제 초안 (평가과제 + 평가자가이드)

| 구분 | 내용 |
|---|---|
| 넣는 것 | 스토리맵(①에서 자동으로 넘어옴, 또는 업로드), 참조 평가과제(pptx/pdf), 참조 평가자가이드(pptx/pdf/docx) |
| 확인 단계 | `isomorph-ac`의 ★정지 표시마다 결과를 보여 준다(예전 과제 풀이 다시 보기 → 새 과제 풀이 짜기 → 자료 나누기). 이용자는 확인하거나 AI에게 고쳐 달라고 한 뒤 넘어간다. |
| 나오는 것 | 두 묶음의 목차. **평가과제**: 구조, 공통 자료, 역할별 자료. **평가자가이드**: 과제 개요, 역량별 행동 지표, 자료별 쟁점과 정답 근거, 평가자 질문, 채점 기준. 공통 편집 화면에서 연다. |
| 서로 연결 | 가이드의 정답 근거마다 과제의 자료·쪽을 연결해 둔다. 과제를 고치면 연결된 가이드 부분에 "함께 확인 필요"를 붙인다. |
| 그림·지도·차트 | 자료의 그림 자리에 만들어 넣거나, 항목 제목 아래 "넣기" 줄에서 그림·지도·차트를 골라 원하는 문단 사이에 새로 넣는다. AI에게 넣을 자리를 제안받을 수도 있다(3-5). |
| 완료 | 점검을 한 번 이상 돌리고 남은 결과가 없으면 완료로 표시한다. |

### 3-4. 공통 편집 화면 (②, ④, ⑤)

#### 3-4-1. 배치

```
┌──────────────┬────────────────────────────────────┬────────────────────┐
│ 목차          │ [전체 점검] [전체 수정 제안]          │ 채팅 / 점검 결과 /  │
│ 평가과제      │        [바뀐 부분 보기] [받기]        │ 수정 기록           │
│  구조         │ 항목 골라 점검 ▸                     │                    │
│  공통 자료    │ ─────────────────────────────────── │ (결과 카드 …)       │
│  역할별 자료  │ (검토 모드 띠)                        │                    │
│ 평가자가이드  │ 항목 제목                             │                    │
│               │ 구분 · 쪽      [이 항목 고쳐 달라고 하기]│                    │
│               │ 넣기 [그림][지도][차트][파일] [AI 제안]│ 고칠 범위: 자료 2   │
│               │ (항목 내용, 그림·지도·차트 자리)        │ [요청 입력] [보내기]│
└──────────────┴────────────────────────────────────┴────────────────────┘
```

- 처음 열면 사용법 3가지를 본문 위에 보여 준다.
- 휴대폰 폭에서는 세 영역을 탭(목차 / 문서 / 채팅·결과)으로 바꿔 보여 준다.

#### 3-4-2. 수정 방법과 고칠 범위

| 방법 | 동작 | 적용 범위 |
|---|---|---|
| 항목 하나 | 목차에서 항목을 누른다. | 지금 보는 항목. 채팅창 위에 "고칠 범위: 자료 2"로 보인다. |
| 여러 항목 | [범위 바꾸기]에서 여러 항목을 체크한다(구분별 [모두] 가능). 또는 목차에서 Ctrl(Mac은 ⌘)을 누른 채 항목을 누른다. | 고른 항목들. "자료 1, 자료 3, 자료 5"처럼 보이고, 4개 이상이면 "… 외 n개"로 줄인다. 목차에는 체크 표시가 붙는다. 항목마다 고친 안이 나오고 검토 모드로 연다. |
| 과제 전체 | [범위 바꾸기]에서 "과제 전체"를 체크한다. | 평가과제와 평가자가이드 전체. AI가 요청에 맞는 곳을 찾아 고친 안 여러 개를 내고 검토 모드로 연다. |
| 글자 일부 | 본문 글자를 드래그하면 작은 메뉴가 뜬다: [AI에게 고쳐 달라고 하기] / [직접 고치기] | 드래그한 글자 |
| 전체 수정 제안 | [전체 수정 제안]을 누른다. | 과제 전체. 요청을 적지 않아도 AI가 고칠 곳 여러 개를 찾아 검토 모드로 연다. |

- [해제]를 누르면 고칠 범위가 지금 보는 항목으로 돌아간다.

#### 3-4-3. 바뀐 부분 확인

- **바뀐 부분 보기**를 켜면 초안과 비교해 지운 글자는 빨간 취소선, 넣은 글자는 초록 바탕으로 보인다.
- 목차에서 바뀐 항목 옆에 점을 찍는다.
- **수정 기록**에는 "누가(이용자/AI), 무엇 때문에(요청 문장, 점검 항목), 어느 항목을" 고쳤는지 한 줄씩 남고, 아무 기록이나 골라 되돌릴 수 있다.
- 고친 항목과 같은 내용을 쓰는 다른 항목(평가자가이드 포함)에 "함께 확인 필요"를 붙인다.

#### 3-4-4. pptx를 항목으로 나누기

과제 파일은 용역마다 방향, 쪽 크기, 자료 개수, 자료 표기가 다르므로 고정 규칙 대신 아래 단서로 AI가 나누고 이용자가 확인한다.

| 단서 | 쓰는 방법 |
|---|---|
| 자료 표기 | 모든 글상자(그룹 도형 안 포함)에서 "자료 3.", "자료3", "[자료 3]", "<자료 3>", "참고자료", "붙임" 같은 표기를 찾는다. 제목 칸에 없을 수 있다. |
| 여러 장 표시 | "(1/4)", "1/4", "계속" 표시가 붙은 연속 슬라이드는 한 자료로 묶는다. |
| 간지 슬라이드 | "역할별 자료", "평가대상자 A" 같은 글만 있는 슬라이드는 구분의 시작으로 본다. 간지가 없으면 모두 "공통 자료"로 둔다. |
| 자료 번호 없는 슬라이드 | 표지, 안내, 상황개요, 가상조직, 마침은 "구조" 구분에 둔다. |
| 쪽 번호 | 슬라이드 안의 인쇄 쪽 번호("- 6 -", "6/20")를 위치 표기에 쓴다. 없으면 슬라이드 순번을 쓴다. |
| 방향·크기 | 나누기에는 쓰지 않고 파일 정보로 기록해 내보낼 때 지킨다. |
| 차트·그림 | 차트 숫자는 읽어서 수치 점검에 쓴다. 그림 자리는 3-5로 만들거나 바꾼다. |

**목차 확인 화면**
- 파일을 처음 열면 AI가 나눈 항목을 표(항목, 쪽, 구분)로 보여 준다.
- 이용자는 틀린 곳만 고친다: 구분 바꾸기, 앞 항목과 합치기, AI에게 나눠 달라고 하기. [AI 제안으로 되돌리기]가 있다.
- 확인한 목차 규칙은 용역별로 저장되어 같은 용역의 다음 파일에 먼저 적용된다.

#### 3-4-5. 파일 형식

- ②의 평가과제는 pptx, 평가자가이드는 pptx 또는 docx(참조 가이드와 같은 형식)로 내보낸다. 평가과제의 방향, 쪽 크기, 레이아웃, 글꼴은 참조 평가과제를 따른다.
- ④와 ⑤는 pptx를 불러와 3-4-4로 나눈 뒤 편집 화면에 보여 준다.
- pptx를 고칠 때는 글자만 바꾸고 레이아웃, 글꼴, 표 모양은 그대로 둔다. 그림·지도·차트는 3-5에서 만든 것으로 바꿔 끼운다. 차트는 가능한 종류면 PPT 차트로 넣는다(3-5).

#### 3-4-6. AI 제안 검토 모드

AI 제안이 여러 개일 때(전체 수정 제안, 여러 항목·과제 전체 요청, 점검 결과, 검토의견 반영) 문서 위에서 하나씩 넘기며 정한다.

| 구성 | 내용 |
|---|---|
| 위쪽 띠 | "제안 2 / 4"와 점검 항목 이름, [검토 끝내기] |
| 문서 | 해당 항목이 열리고, 바뀌는 자리에 지운 글자·넣은 글자가 문서 안에 표시된다. |
| 이유 | 제안 이유, 반영하면 함께 확인해야 할 다른 항목 수 |
| 버튼 | [반영] / [다른 안 제안받기] / [넘기기]. 키보드 → 키로 넘긴다. |
| 끝 | "4건 가운데 3건 반영, 1건 넘김" 요약과 [반영한 것 모두 되돌리기]. 넘긴 제안은 점검 결과에 남는다. |

#### 3-4-7. 점검 결과 보기

점검 버튼은 관리자가 등록한 점검 항목(4-3)으로 만들어진다.

- 문서 위 해당 글자에 점검 항목 색으로 밑줄을 긋는다.
- 결과 칸의 카드는 "점검 항목 · 위치 · 이유" 한 줄로 접혀 있고, 누르면 바뀌는 부분(지운 글자·넣은 글자), [직접 다듬기], [반영] / [다른 안 제안받기] / [반영 안 함]이 펼쳐진다. 한 번에 한 장만 펼쳐진다.
- 결과가 여러 개면 [하나씩 검토]로 검토 모드(3-4-6)를 연다.
- 추가 점검이나 다른 수정은 채팅으로 요청한다.

### 3-5. 그림·지도·차트

**넣는 곳 (버튼 위치)**

- 무엇을 넣을지 먼저 고르고, 그다음 넣을 곳을 고른다. 종류마다 만드는 창이 다르므로(그림 4장 고르기, 지도 편집기, 차트 데이터 표) 이용자는 "무엇을"을 먼저 정해야 다음 화면을 짐작할 수 있다.
- 버튼은 이용자가 보고 있는 것 옆에 둔다. 마우스를 올려야만 보이는 버튼은 처음 쓰는 사람이 찾지 못하고 휴대폰에서는 쓸 수 없으므로 쓰지 않는다.

| 위치 | 버튼 | 하는 일 |
|---|---|---|
| 항목 제목 아래 "넣기" 줄 | [그림] [지도] [차트] [파일 올리기] (아이콘 + 글자), 오른쪽 끝에 [AI에게 자리 제안받기] | 종류를 누르면 그 버튼이 눌린 상태로 바뀌고, 본문 문단 사이마다 [+ 여기에 지도 넣기]처럼 고른 종류가 적힌 자리가 나타난다. 자리를 누르면 그곳에 그림 자리가 생기고 바로 만드는 창이 열린다. [취소] 또는 Esc로 그만둔다. 파일 올리기는 파일을 먼저 고른 뒤 같은 방법으로 넣을 곳을 고른다. |
| 표 머리 오른쪽 | [차트로 만들기] (차트 아이콘) | 그 표 바로 아래에 차트 자리를 만들고, 그 표를 데이터로 채운 차트 만들기 창을 연다. 표가 있을 때만 보인다. |
| 그림 자리 카드 | [그림 만들기] / [지도 만들기] / [차트 만들기] → 넣은 뒤 [다시 만들기], [위로] / [아래로] / [빼기] | 자리 하나를 만들고 옮기고 지운다. 넣기·옮기기·빼기는 수정 기록에 남고 되돌릴 수 있다. |

- 자료 안에 이미 있는 자리("[그림] 제목: 설명", "[차트] 제목")는 카드로 보인다. 제목에 "지도", "위치도", "배치도"가 들어가면 지도 만들기로 열린다.
- 새 자리를 만든 직후 열린 만들기 창에서 [취소]하면 그 빈 자리도 함께 뺀다. 아무것도 만들지 않았는데 빈 자리만 남으면 이용자가 직접 지워야 하기 때문이다.
- 바뀐 부분 보기를 켜면 넣기 버튼은 누를 수 없다(무엇을 고쳤는지 보는 화면이기 때문).
- 넣은 그림·지도·차트는 "그림·지도·차트 일치" 점검(4-3-2) 대상이다.

**AI 자리 제안**

AI가 자료 글을 읽고 그림·지도·차트가 있으면 이해가 빨라지는 곳을 찾아, 자리와 종류를 제안한다.

| 순서 | 동작 |
|---|---|
| 1 | "넣기" 줄의 [AI에게 자리 제안받기]. 대상은 고칠 범위(3-4-2)에 든 항목이다(기본은 지금 보는 항목). |
| 2 | 제안 자리가 문서의 그 위치에 점선 카드로 나온다. 카드에는 종류, 제목, 그릴 내용, **이유**(예: "3년 치 숫자 비교가 글로만 있음")가 있다. |
| 3 | 카드마다 [반영] / [다른 안 제안받기] / [반영 안 함]. 여러 개면 [모두 반영] / [모두 반영 안 함]도 있다. [반영]하면 그 자리에 그림 자리가 생기고, [만들기]로 이어서 만든다. 반영 직후 알림의 [되돌리기]로 무를 수 있다. |
| 4 | 위쪽 제안 줄에 "이 항목 n개 · 다른 항목 n개"를 보여 주고, 다른 항목 이름을 누르면 그 항목으로 간다. 제안하지 않은 곳은 "제안하지 않은 곳 n곳과 이유"에 접어 둔다. |

제안 규칙(지침 `ac-figure`의 references/placement.md):
- 그림·차트가 응시자가 스스로 찾거나 계산해야 할 값을 미리 보여 주면 난이도가 바뀐다. 평가자가이드가 "계산"이나 "비교"로 채점하는 숫자는 차트로 만들지 않고 표 그대로 둔다. 제안하지 않은 이유도 함께 알린다.
- 차트: 같은 기준의 숫자가 3개 이상(연도·지역·항목) 있을 때만.
- 지도: 위치 관계(거리, 방향, 인접)가 판단에 쓰이는 장소가 2곳 이상일 때만.
- 사진·그림: 신문기사, 민원, 현장 보고처럼 실제 문서라면 사진이 있을 자료에만.
- 이미 그림이 있는 문단, 표지·안내문, 평가자가이드에는 제안하지 않는다.
- 한 자료에 2개까지. 쪽 수와 양식(3-4-4의 목차 규칙)을 바꾸지 않기 위해서다.

**그림 만들기 (예: 신문기사 사진)**

| 순서 | 동작 |
|---|---|
| 1 | AI가 자료 글을 읽고 "그릴 장면"을 미리 적는다. 이용자가 고칠 수 있다. |
| 2 | 느낌(보도 사진 / 일러스트 / 단순한 그림)과 비율(4:3 / 3:4 / 16:9)을 고른다. |
| 3 | [그림 4장 만들기] → 하나를 고르고 [고른 그림 넣기]. 마음에 들지 않으면 [다른 그림 4장 더]. |

- 실존 인물, 실제 기관 로고·상표, 알아볼 수 있는 실제 장소는 그리지 않는다. 가상 기관·지역을 다루는 과제와 맞추고 응시자의 유불리를 막기 위해서다.
- 그림 안에는 글자를 넣지 않는다. 이미지 생성 모델은 한글을 정확히 쓰지 못하므로 설명 글은 과제 지면에 쓴다.

**지도 만들기 (포털 안의 지도 편집기)**

과제 지도 제작기의 기능을 포털 안에 직접 만든다. 별도 도구로 나가지 않는다.

| 순서 | 동작 |
|---|---|
| 1 | [지도 초안 만들기] 또는 [빈 지도에서 시작]. 초안은 프로젝트의 자료 글 전체를 읽어 지명, 시설, 후보지, 도로·철도, 하천, 사업 구역을 찾아 초안을 그리고 지도 편집기를 연다. |
| 2 | 편집기에서 고친다(아래 표). 고칠 점을 AI에게 말로 요청할 수도 있다(예: "후보지 B를 하천 남쪽으로 옮겨 줘"). |
| 3 | 원고에 근거가 없어 정한 "가정" 항목을 확인한다. 가정 항목이 남아 있으면 "가정 항목을 확인했습니다"에 체크해야 넣을 수 있다. 확인한 뒤 가정 항목이 새로 생기면(AI 요청, 근거를 가정으로 바꿈, 작업 파일 열기) 체크가 풀린다. |
| 4 | [이 지도 넣기]. 지도와 편집 내용(작업 파일)이 프로젝트에 저장되어, 그림 자리의 [다시 만들기]로 언제든 이어서 고친다. |

| 편집기 기능 | 내용 |
|---|---|
| 범례 팔레트 | 지점(후보지, 주요 시설, 주요 도시, 지역명), 선(일반도로, 고속도로, 철도, 하천), 면(사업 구역 경계, 공원·녹지, 하천·수면, 규제·보호 구역)을 골라 지도에 그린다. 지점은 한 번 누르기, 선·면은 점을 차례로 누르고 두 번 누르거나 Enter로 마친다. |
| 선택·이동 | 항목을 눌러 고르고 끌어서 옮긴다. 선·면은 꼭짓점을 끌어 모양을 고친다. 키보드: 화살표로 옮기기, Delete로 지우기, Esc로 그리기 취소 |
| 속성 | 이름, 범례 항목, 근거(원고 근거 / 가정, 가정이면 무엇을 정했는지), 지도에 이름 표시, [복제], [지우기] |
| 목록 | 전체 항목과 근거 표시. 가정 항목 수를 위에 보여 준다. |
| 거리표 | 후보지와 시설·도시 사이의 직선거리(km). 축척으로 계산한다. |
| 양식 | 지도 제목, 범례·축척·방위표 표시, 축척(1km당 길이) |
| 기타 | 실행 취소·다시 실행, 내보내기(SVG 편집용 / PNG), 작업 파일(.json) 저장·열기 |

**차트 만들기**

| 순서 | 동작 |
|---|---|
| 1 | 데이터를 고른다. 표의 [차트로 만들기]로 열면 그 표가 이미 골라져 있다. 같은 항목이나 다른 항목에 있는 표를 고르면 계산 코드가 숫자와 단위를 읽어 온다(예: "410만 건" → 410, 단위 "만 건"). 표가 없으면 직접 입력한다. 값은 표 칸에서 바로 고치고, 행·열을 더할 수 있다. |
| 2 | 보여 줄 값(계열)과 차트 종류를 고른다. 제목과 단위를 적는다. |
| 3 | 미리보기(막대·점 위에 값 표시)를 보고 [차트 넣기]. 모양은 AI에게 말로 고쳐 달라고 할 수도 있다. 넣은 차트의 카드에는 "PPT에서 고칠 수 있는 차트" 또는 "그림(PNG) + 데이터 표로 넣음"이 적힌다. |

| 차트 종류 | 과제 파일(pptx)에 넣는 방식 |
|---|---|
| 세로 막대, 가로 막대, 누적 막대, 꺾은선, 원 | **PPT 차트**로 넣는다. 데이터가 차트 안에 들어 있어 PowerPoint에서 값과 모양을 바로 고칠 수 있다(python-pptx의 차트 기능). |
| 막대+꺾은선(이중 축) 같은 섞인 차트 | **그림(PNG)과 데이터 표**로 넣는다. 이 종류는 python-pptx가 기본으로 만들지 못해 차트 XML을 직접 다뤄야 하므로, PPT 차트로 넣는 것은 다음 단계로 미룬다. 화면에서 고를 때 이 차이를 미리 알린다. |
| 평가자가이드(docx)에 넣을 때 | 그림(PNG) |

- 차트의 숫자는 계산 코드가 읽은 값을 쓴다. 자료 글·표의 숫자와 다르면 "그림·지도·차트 일치" 점검에서 알린다.

**파일 올리기**
- 가진 그림 파일(png, jpg, svg)을 그대로 넣는다. 실존 인물·로고가 들어간 파일인지는 "그림·지도·차트 일치" 점검이 다시 확인한다.

### 3-6. ③ 검토회의 보고서

화면은 세 단계다: **1. 녹취록 확인 → 2. 양식 칸 확인 → 3. 미리보기·받기**

**녹취록 확인 (클로바노트와 같은 방식)**

| 순서 | 동작 |
|---|---|
| 1 | 음성 파일(mp3, m4a, wav)을 올리고 참석 인원(자동, 3~5명)을 고른다. |
| 2 | 서버가 음성을 글로 바꾸고 화자를 나눈다. 결과는 `화자 1`~`화자 5`, 발언 시각, 발언 내용이다. |
| 3 | 화자를 누르고 이름, 소속, 구분(검토위원 / 발주처 / 개발사)을 적으면 그 화자의 모든 발언에 적용된다. 구분이 없는 화자가 있으면 칸을 채우기 전에 알리고 화자 정보로 안내한다. |
| 4 | 시각을 누르면 그 부분부터 재생된다. 잘못 들린 글자는 그 자리에서 고친다. |
| 5 | 화자가 잘못 나뉜 발언은 줄마다 있는 화자 선택으로 바꾼다. |

**양식 칸 확인과 미리보기 (양식이 용역마다 달라도 됨)**

| 순서 | 동작 |
|---|---|
| 1 | 저장된 양식을 고르거나 hwpx 양식을 올린다. hwp 양식은 한글에서 "다른 이름으로 저장 → hwpx"로 한 번 바꿔 올린다(hwp를 올리면 이 방법을 안내한다). |
| 2 | AI가 채울 칸을 찾아 "AI가 칸 8개를 찾았습니다"처럼 요약한다. 칸마다 [AI가 채움] / [비워 둠] / [직접 입력]은 [칸별로 고치기]에서 바꾼다. |
| 3 | 이전 회차 내용이 들어 있는 양식이면 그 문체와 표기를 예시로 쓴다(예: "~하겠음", "[자료3. 제목(2/3), 6page]"). |
| 4 | 평가과제 pptx를 함께 고르면 "자료 3 두 번째 장" 같은 말을 양식의 위치 표기(자료 제목, 장, 인쇄 쪽)로 바꿔 적는다. |
| 5 | 미리보기에서 칸마다 근거 발언으로 이동할 수 있다. 직접 고치거나 AI에게 고쳐 달라고 한다. |
| 6 | [hwpx로 받기]. 확인한 칸 구성은 "발주처·용역명"으로 저장되어 다음 회차에 다시 쓴다. |

**검토회의 결과 양식의 칸 예시**

| 칸 | 채우는 방법 |
|---|---|
| 제목줄(연도, 기관, 직급, 기법, 차수) | 프로젝트 정보 |
| 건명, 일시 | 프로젝트 정보 + 녹음 파일 날짜 |
| 참석인원(총 n명, 구분별 소속·이름) | 화자 정보 |
| 회의내용 표: 위치 행 | 의견이 가리키는 자료의 위치 표기. 첫 행은 "과제 전반" |
| 회의내용 표: 검토위원 의견 | 검토위원 발언 요약 |
| 회의내용 표: 발주처 의견 | 그 의견 행과 관련된 발주처 발언 요약. 관련 발언이 없는 행만 비운다. |
| 회의내용 표: 개선 및 반영 방향 | 개발사 답변과 회의 결론을 "~하겠음" 문체로 요약 |
| 향후일정 표 | 회의에서 나온 다음 일정 |

- 회의내용 표는 "위치 행 + 내용 행"이 한 묶음으로 반복되므로, AI가 의견 수만큼 묶음을 늘려 채운다.
- 결과는 hwpx로 내보낸다(한글 2014 이후 버전에서 열림).

### 3-7. ④ 검토의견 반영

| 순서 | 동작 |
|---|---|
| 1 | 고칠 평가과제 pptx를 고른다. ②에서 만든 것이 있으면 자동으로 선택되고 평가자가이드도 함께 불러온다. 새 파일은 목차 확인(3-4-4)을 거친다. |
| 2 | 수정 요청 목록은 ③ 보고서의 의견 행을 그대로 가져온다. 항목마다 위치, 검토위원 의견, 발주처 의견, 반영 방향, 근거 발언 시각이 있다. ③을 거치지 않았으면 녹취록에서 뽑는다. |
| 3 | 반영할 요청만 체크한다. 서로 부딪치는 요청은 "의견 엇갈림"으로 표시한다. |
| 4 | [고친 안 만들기] → AI가 요청마다 고친 안을 만들고, 자료·DB의 다른 평가과제·평가자가이드를 찾아 근거를 붙인다. |
| 5 | 검토 모드(3-4-6)로 열려 하나씩 [반영] / [다른 안 제안받기] / [넘기기]를 고른다. |
| 6 | [pptx로 받기], [반영 내역표 받기](요청 → 반영 여부 → 고친 위치). |
| 7 | [검토 교훈 남기기]를 누르면 다른 과제에도 쓸 만한 교훈을 정리해 `isomorph-ac`의 `references/review-lessons.md`에 넣자는 제안을 관리자에게 보낸다(4-2-3 제안 대기). |

### 3-9. AI에게 고쳐 달라고 하기

모든 결과 아래에 같은 모양의 AI 수정 요청 상자를 둔다(2-2 원칙 10). 이용자 화면에서 쓰는 곳은 다음과 같다.

| 화면 | 고칠 대상 | 요청 예시 |
|---|---|---|
| ① 평가 조건 | 해결과제 수, 측정 역량, 업무 관련성 | 해결과제를 3개로 늘려 줘 |
| ① 구조 분석 | 구조 항목 | 규모를 사업비 10억 원 안팎으로 바꿔 줘 |
| ① 해결과제 후보 | 후보 5개 | 환경 분야는 빼고 다시 만들어 줘 |
| ① 스토리맵 | 스토리맵 내용 | 역할 간 갈등을 더 분명하게 해 줘 |
| ② 확인 단계 | 그 단계 결과 | 핵심 판단 지점을 하나 더 넣어 줘 |
| 편집 화면 | 고칠 범위(3-4-2) 안의 내용 | 자료 1, 3, 5를 더 짧게 줄여 줘 |
| 목차 확인 | 항목 나누기·구분 | 자료 3을 장별로 두 항목으로 나눠 줘 |
| 편집 화면: AI 자리 제안 | 제안된 그림·지도·차트 자리 | 표가 있는 자료에만 제안해 줘 |
| 그림·지도·차트 | 지도 내용, 차트 모양 | 후보지 B를 하천 남쪽으로 옮겨 줘 / 고장 비율을 꺾은선으로 함께 보여 줘 |
| ③ 녹취록 | 화자 지정, 발언 글자 | 00:13:30 발언은 화자 1의 발언이야 |
| ③ 양식 칸 | 칸별 채우는 방법 | 향후일정은 직접 입력으로 바꿔 줘 |
| ③ 미리보기 | 보고서 문장 | 반영 방향 문장을 더 짧게 줄여 줘 |
| ④ 수정 요청 목록 | 요청 나누기·합치기·고르기 | 마지막 요청을 둘로 나눠 줘 |

- 앞 단계 결과를 고치면 그 결과를 쓰는 다음 단계에도 반영한다. 예: ③ 보고서 문장을 고치면 ④ 수정 요청 목록에도 들어간다.

## 4. 관리자 기능

### 4-1. 관리자 화면 구성

| 메뉴 | 하는 일 | 절 |
|---|---|---|
| 지침 관리 | 기능별 지침(스킬 또는 직접 쓴 지침) 보기·고치기·AI에게 고쳐 달라고 하기, 저장 전 규칙 점검, 시험 실행, 수정 기록, 제안 대기 | 4-2 |
| 점검 항목 관리 | 점검 버튼이 될 점검 항목 등록·고치기·순서 바꾸기·지우기 | 4-3 |
| 자료·DB 관리 | 기출 DB, 주제풀, 실무 DB, 역량 정의, 참고 문서, 용역 설정 | 4-4 |
| 양식·구조 관리 | 보고서 양식, 과제 파일 목차 규칙, 그림·지도·차트 양식 | 4-5 |
| 설정 | 기능 켜기/끄기, 이용자 권한 | 4-6 |

- 관리자 화면 버튼은 관리자 계정에만 보인다. 관리자 화면에서 [이용자 화면으로]를 누르면 돌아간다.
- 관리자 화면도 휴대폰 폭에서 가로로 넘치지 않는다.
- 관리자 화면에서 AI 수정 요청 상자를 쓰는 곳:

| 화면 | 고칠 대상 | 요청 예시 |
|---|---|---|
| 지침 관리 | SKILL.md, references/ 문서, 직접 쓴 지침 | 후보를 5개에서 3개로 줄여 줘 |
| 점검 항목 | 점검 지침 | 기준을 더 구체적으로 써 줘 |

### 4-2. 지침 관리

#### 4-2-1. 스킬 불러오기

관리자가 기존 스킬 폴더를 zip으로 올리면 포털이 다음처럼 나눠 쓴다.

| 스킬 구성 | 포털에서 쓰는 방법 |
|---|---|
| `SKILL.md` 머리말(name, description) | 기능 선택 화면의 이름과 설명 |
| `SKILL.md` 본문 | 해당 기능의 지침(시스템 프롬프트) |
| `references/` 문서 | 자료·DB 관리의 참고 문서에 넣고, 지침이 언급할 때 찾아 함께 넣는다. |
| `examples/` 문서 | 작성 예시, 그리고 시험 실행(4-2-3)의 예시 입력 |
| `scripts/` 코드 | 서버의 격리된 실행 환경에서 돌린다(예: pptx 읽기·쓰기, 표 계산). |

- 스킬은 웹 검색, 파일 읽기·쓰기, 코드 실행 도구를 쓴다고 가정하고 쓰여 있다. 포털은 같은 도구를 모델에 제공하고, 모델은 도구 호출(function calling)을 지원해야 한다.
- 도구로 처리할 수 없는 기능이나 스킬이 없는 기능은 관리자가 지침을 직접 쓴다.

#### 4-2-2. 기능별 지침 연결

| 기능 | 지침 | 방식 |
|---|---|---|
| ① 주제 탐색 | `ac-topic-storymap` | 스킬 |
| ② 과제 초안 | `isomorph-ac` | 스킬 |
| ③ 검토회의 보고서 | 녹취록 요약·양식 칸 채우기 지침 | 직접 쓴 지침 |
| ④ 검토의견 반영 | 수정 요청 반영 지침(필요하면 `isomorph-ac` 일부 참조) | 직접 쓴 지침 |
| ⑤ 검수 | 점검 항목(4-3) | 점검 버튼 |
| 그림·지도·차트 | `ac-figure` (자리 제안, 그림 장면 쓰기, 지도 항목 뽑기, 차트 종류 추천. 숫자는 계산 코드가 읽음) | 스킬 |

- `ac-figure`는 ②④⑤ 어느 단계에서 불러도 같은 규칙을 쓴다. 과제의 정답·난이도를 바꾸지 않는 규칙이 들어 있어, 용역이 달라도 그대로 다시 쓴다. 스킬 원본은 저장소의 `skills/ac-figure/`에 둔다.

#### 4-2-3. 지침 관리 화면

| 기능 | 내용 |
|---|---|
| 파일 보기 | 왼쪽에 스킬 폴더의 파일 목록(SKILL.md, references/, scripts/, examples/), 오른쪽에 내용 |
| 직접 고치기 | SKILL.md, references/, examples/ 문서는 화면에서 고친다. scripts/ 코드는 보기만 하고, 고치기는 개발 담당 권한으로 둔다. |
| AI에게 고쳐 달라고 하기 | 파일 아래 AI 수정 요청 상자에 적는다. AI는 4-2-4 규칙을 지켜 고친 안을 만들고, 바뀌는 부분과 규칙 점검 결과를 함께 보여 준다. |
| 저장 전 규칙 점검 | 저장할 때 4-2-4의 자동 점검을 돌린다. 통과하지 못하면 이유를 보여 주고 그래도 저장할지 묻는다. |
| 시험 실행 | 예시 파일로 지금 쓰는 버전과 고친 버전의 결과를 나란히 보여 준다. |
| 수정 기록 | 저장할 때마다 고친 사람, 날짜, 바꾼 이유가 남는다. 직전 수정을 되돌릴 수 있다. |
| 제안 대기 | 다른 화면에서 들어온 스킬 수정 제안(예: ④의 검토 교훈)을 모아 보여 준다. 관리자가 [반영] / [반영 안 함]을 고른다. |

#### 4-2-4. AI가 스킬을 고칠 때 지킬 규칙

| 규칙 | 이유 | 자동 점검 |
|---|---|---|
| 머리말의 `name`은 바꾸지 않는다. | 이름이 바뀌면 기능과 스킬의 연결이 끊긴다. | 이름이 그대로인지 |
| `description`에 "무엇을 하는지"와 "언제 쓰는지"를 함께 적는다. | 모델은 description을 보고 스킬을 쓸지 정한다. | 비어 있지 않은지 |
| SKILL.md 본문은 500줄 이하로 둔다. 길어지면 references/ 문서로 옮기고 "언제 읽을지"를 적는다. | 본문은 매번 통째로 읽히므로 짧을수록 정확하고 빠르다. | 줄 수 |
| 300줄이 넘는 references/ 문서에는 첫머리에 목차를 둔다. | 필요한 부분만 찾아 읽게 한다. | 줄 수와 목차 |
| SKILL.md가 가리키는 references/·scripts/ 경로는 실제로 있어야 한다. | 없는 파일을 가리키면 그 단계가 실패한다. | 경로가 파일 목록에 있는지 |
| "반드시", "절대" 같은 강한 말 대신 이유를 적는다. | 이유를 알면 처음 보는 경우에도 맞게 판단한다. | 강한 말 개수(경고만) |
| 특정 과제 하나에만 맞는 규칙을 넣지 않는다. | 스킬은 여러 용역에 반복해 쓰인다. | 없음(사람이 확인) |
| 고친 뒤 예시 파일로 이전 버전과 결과를 비교한다. | 고친 것이 실제로 나은지 확인한다. | 시험 실행 |

#### 4-2-5. 스킬의 확인 지점

- 스킬 본문에 "★정지"로 표시된 단계는 AI가 멈추고 이용자의 확인을 받는 지점이다.
- 포털은 SKILL.md에서 ★정지 표시를 찾아 화면의 **확인 단계**로 보여 준다. 단계마다 결과, AI 수정 요청 상자, [확인하고 다음으로]를 둔다.
- 관리자가 ★정지를 넣거나 빼면 이용자 화면의 확인 단계도 그대로 바뀐다.

### 4-3. 점검 항목 관리

#### 4-3-1. 등록 칸

| 칸 | 설명 | 예시 |
|---|---|---|
| 이름 | 버튼에 보일 이름 | 현실적합성 |
| 지침 | 무엇을 어떤 기준으로 찾을지 | 실제 있는 제도인가, 그 직급에 그 권한이 있는가, 규모가 현실적인가, 날짜와 요일이 맞는가 |
| 계산 코드 사용 | 숫자 계산이 필요한 항목이면 켠다. | 수치 계산에서 켬 |
| 표시 색 | 문서 위 밑줄과 카드에 쓰는 색 | 주황 |
| 보이는 단계 | 버튼을 보일 단계 | ②, ④, ⑤ |
| 순서·사용 여부 | 버튼 순서, 숨김 | |

- 등록한 항목은 편집 화면의 "항목 골라 점검"에 버튼으로 나오고, [전체 점검]을 누르면 모두 돌아간다.
- 지울 때는 "정말 지울까요?"를 한 번 더 묻는다. 순서는 [위로]로 바꾼다.
- 점검 지침은 AI에게 고쳐 달라고 할 수 있다.

#### 4-3-2. 기본 점검 항목 (관리자가 고치거나 지울 수 있음)

| 이름 | 찾는 것 | 계산 코드 |
|---|---|---|
| 현실적합성 | 실제와 맞지 않는 제도·권한·규모·일정 | 날짜·요일 |
| 오탈자 | 맞춤법, 띄어쓰기, 오타, 기관명·인물명 표기 불일치 | — |
| 수치 계산 | 예산 합계, 비율, 증감률, 인원 합계. 표와 차트 안의 숫자 포함 | 사용 |
| 자료 간 일치 | 같은 사실(금액, 날짜, 인물, 직위)이 자료마다 다르게 적혔는지, 자료끼리 조건이 충돌하는지 | 사용 |
| 근거 없는 내용 | 다른 자료에 근거가 없는 주장이나 결론 | — |
| 표현 | 뜻이 모호한 용어, 정답을 알려 주는 표현, 차별적 표현 | — |
| 구성 점검 | 자료 번호 누락·중복, 표지의 "총 n장"과 실제 장수, 쪽 번호 연속 | 사용 |
| 과제-가이드 일치 | 가이드가 정답 근거로 든 자료·수치가 과제에 있는지, 과제의 숫자와 가이드의 계산 답이 맞는지 | 사용 |
| 그림·지도·차트 일치 | 그림·지도의 지명, 거리, 후보지 위치가 자료 글과 맞는지. 지도의 "가정" 항목이 확인 없이 남았는지. 차트의 숫자가 자료 글·표의 숫자와 같은지. 그림에 실존 인물·로고·글자가 들어갔는지. 그림·차트가 응시자가 스스로 찾거나 계산해야 할 값(정답 근거)을 미리 보여 주는지 | 사용 |

### 4-4. 자료·DB 관리

| 탭 | 들어 있는 것 | 쓰는 곳 |
|---|---|---|
| 기출 DB | 연도, 발주처, 직급, 기법, 해결과제(해결과제명·측정 역량), 서버 파일명 | ① 드롭다운, 평가 조건, 구조 분석, 겹침 대조 |
| 발주처 주제풀 | 발주처, 직급, 연도, 주제, 선정 여부, 서버 파일명 | ① 겹침 대조 |
| 실무 DB | 발주처, 연도, 부서, 담당 업무 | ① 무관 조건일 때 발주처 실무와 겹치는지 대조 |
| 역량 정의 | 기관, 직급, 역량, 하위요소 | ① 측정 역량, 역량-내용 연계 분석 |
| 참고 문서 | 평가과제, 평가자가이드, 기관 자료 파일 | ②④ 참고 검색 |
| 용역 설정 | 용역별 평가 조건, 구조 분석 결과, 확정 주제, DB 기준 정보(행 수, 최근 연도, 서명) | ① 2·3단계 결과 재사용 |

- **드롭다운 연동**: ①의 발주처·직급 목록은 기출 DB와 주제풀의 값으로 만든다. 행을 추가하면 바로 목록에 나온다.
- **RAG 연결**: 파일명은 사내 서버의 파일을 가리킨다. 포털은 파일명으로 서버 파일을 찾아 색인을 만들고, 화면에서 파일명을 누르면 찾은 부분과 파일 위치를 보여 준다. 서버에 없는 파일은 "서버에 파일 없음"으로 표시한다.
- **관리 기능**: 행 추가·고치기·지우기, CSV 가져오기·내보내기, [색인 다시 만들기]. 색인을 다시 만들어 DB 기준 정보가 바뀌면 ①에서 구조 분석을 다시 한다.

### 4-5. 양식·구조 관리

#### 4-5-1. 보고서 양식

- 이용자가 ③에서 확인한 hwpx 양식과 칸 구성이 "발주처·용역명"으로 저장된다. 목록에는 양식 이름, 파일 형식, 칸 수, 최근 사용일이 보이고 [칸 구성 보기]로 연다.
- 관리자는 칸 구성을 보고·고치고·지운다. 같은 용역의 다음 회의에서 이용자는 저장된 양식을 고르기만 한다.

#### 4-5-2. 과제 파일 목차 규칙

- 이용자가 목차 확인(3-4-4)에서 확인한 규칙이 용역별로 저장된다. 칸: 용역, 방향·쪽 크기(예: 세로·A4, 가로·16:9), 자료 표기(예: "자료 N.", "[자료 N]"), 구분 규칙(예: 구조 / 공통 자료 / 역할 간지별 구분).
- 관리자는 규칙을 보고·고치고·지운다. 같은 용역의 다음 파일에는 이 규칙이 먼저 적용된다.

#### 4-5-3. 그림·지도·차트 양식

모든 과제에 같은 모양이 나오도록 관리자가 정한다. 그리는 규칙(무엇을 그리고 무엇을 그리지 않는지)은 지침 `ac-figure`에, 모양(색, 글꼴, 기본값)은 이 화면에 둔다. 규칙과 모양을 나누면 관리자가 지침을 고치지 않고도 모양만 바꿀 수 있다.

| 칸 | 내용 | 쓰는 곳 |
|---|---|---|
| 지도 범례 항목 | 항목마다 이름, 종류(지점·선·면), 색, 사용 여부. 항목 추가 | 지도 편집기 팔레트와 범례, AI 지도 초안 |
| 차트 색 | 계열 색 4개(강조는 고른 막대에 테두리를 두르고 나머지를 흐리게 한다) | 차트 미리보기, PPT 차트 |
| 차트 글꼴 | 과제 파일과 같은 글꼴 | 차트 미리보기, PPT 차트 |
| 그림 기본값 | 기본 느낌(보도 사진 / 일러스트 / 단순한 그림), 기본 비율 | 그림 만들기 창 |

- 바꾼 값은 바로 저장되고, 새로 만드는 그림·지도·차트부터 적용된다. 이미 넣은 것은 [다시 만들기]를 해야 바뀐다.

| 설정 | 켜면 | 끄면 |
|---|---|---|
| 웹 검색 | ① 시의성 확인과 ④ 참고 조사에 웹 검색을 쓴다. | 사내 참고자료로만 한다. |
| 그림 만들기 | 그림 자리에 [그림 만들기]가 나온다. | [그림 만들기]가 사라지고 그림 파일을 직접 올린다. 지도·차트 만들기는 그대로 쓴다(이미지 생성 모델이 필요 없음). |
| AI 자리 제안 | 편집 화면 "넣기" 줄에 [AI에게 자리 제안받기]가 나온다. | 버튼이 사라진다. |
| 이용자 권한 | 사람마다 이용자 / 관리자를 정한다. | — |

- 시안 설정 화면의 "시안 체험: 진행 중 실패 화면 보기"는 실패 화면을 확인하기 위한 것이므로 만들지 않는다.

## 5. 시스템 요구사항

### 5-1. 서버 구성 요소 (사내 설치)

| 역할 | 후보 (오픈소스) | 비고 |
|---|---|---|
| 언어 모델 | 한국어 성능과 도구 호출을 지원하는 모델 | 과제 전체와 가이드를 넣으려면 입력 길이 128K 이상 |
| 이미지 생성 | 사내 설치 가능한 이미지 생성 모델(예: FLUX 계열, Stable Diffusion 계열) | GPU 필요. 상업적 이용이 가능한 사용권인지 확인한다. 그림 안에 글자는 넣지 않는다. |
| 음성 → 글 | Whisper 계열(large-v3 등) | GPU 필요. 1시간 회의 처리 시간을 시험으로 확인한다. |
| 화자 구분 | pyannote 계열 | 3~5명 회의 녹음으로 정확도를 시험한다. |
| 참고자료 검색(RAG) | 문서 임베딩 + 벡터 DB | 자료·DB의 파일명으로 서버 파일을 찾아 색인. 발주처·연도·기법·직급으로 거른다. |
| 지도 편집기 | 포털 안에 직접 구현(과제 지도 제작기의 기능을 옮김) | 지도는 SVG로 그리고 PNG·SVG·작업 파일(.json)로 저장. 초안의 항목 추출은 사내 언어 모델 |
| 차트 | python-pptx 차트 기능(PPT 차트), 미리보기는 SVG | 섞인 차트(막대+꺾은선)는 1차에 그림(PNG)으로 넣는다. |
| pptx 처리 | python-pptx | 방향·쪽 크기와 상관없이 읽고 쓴다. 그룹 도형 안 글과 차트 숫자도 읽는다. |
| hwp 읽기 | olefile + 한글 5.0 형식 해석 코드 | 자료·DB에 올린 hwp 문서를 검색용으로 읽는다. 양식 채우기에는 쓰지 않는다. |
| hwpx 쓰기 | hwpx 안의 XML 직접 처리 | 칸 단위로 채운다. |

### 5-2. 프로그램에서 지켜야 할 규칙

아래는 AI 지침에만 맡기지 않고 코드에서 막는다. 모델이 지침을 어겨도 결과가 틀리지 않게 하기 위해서다.

| 규칙 | 구현 |
|---|---|
| AI 결과는 이용자가 [반영]하기 전에는 문서에 들어가지 않는다. | 고친 안은 따로 보관하고, 반영할 때 수정 기록과 함께 본문을 바꾼다. |
| 숫자 계산은 계산 코드가 한다. | 합계·비율·증감률·날짜·요일, 표·차트 숫자 읽기("410만 건" → 410, 단위 "만 건")는 코드로 한다. |
| ★정지 단계에서는 다음 단계로 넘어가지 않는다. | 이용자의 [확인하고 다음으로]를 받은 뒤에만 다음 단계를 요청한다. |
| ① 전체 확정 전에는 스토리맵을 쓰지 않는다. | 6단계 승인 후에만 스토리맵 요청 |
| 지도의 가정 항목을 확인하기 전에는 넣지 않는다. | 가정 항목이 있으면 확인 체크 전까지 [이 지도 넣기] 비활성. 가정 항목이 새로 생기면 체크를 푼다. |
| 섞인 차트는 PPT 차트로 만들지 않는다. | 막대+꺾은선은 PNG + 데이터 표로 내보낸다. |
| AI 자리 제안은 한 자료에 2개까지(이미 있는 그림 포함). | 모델 결과를 받은 뒤 코드로 한 번 더 자른다. |
| 새 자리를 만든 직후 만들기를 취소하면 빈 자리를 뺀다. | 결과가 없는 새 자리는 창을 닫을 때 지운다. |
| pptx는 글자만 바꾼다. | 레이아웃·글꼴·표 모양은 원본 그대로 두고 글상자 글과 그림만 바꿔 끼운다. |
| 지침 저장 전 규칙 점검 | 4-2-4의 자동 점검을 돌리고, 통과하지 못하면 이유와 [그래도 저장]을 보인다. |
| 지울 때만 한 번 더 묻는다. | 점검 항목·자료 행 지우기 등 되돌릴 수 없는 동작만 확인 창을 띄운다. |
| 관리자 화면은 관리자 권한에만 보인다. | 화면에서 숨기는 것과 함께 서버에서도 권한을 확인한다. |
