# 과제 그림·지도·차트

과제 자료의 그림·지도·차트는 응시자가 상황을 빨리 파악하도록 돕는 장치다. 동시에 응시자가 스스로 찾거나 계산해야 할 것을 대신 보여 주면 과제의 난이도와 채점 기준이 바뀐다. 이 스킬의 모든 규칙은 이 두 가지를 함께 지키기 위한 것이다.

## 공통 규칙

1. **정답을 미리 보여 주지 않는다.** 평가자가이드가 "계산", "비교", "찾아냄"으로 채점하는 값(증감률, 합계, 거리, 순위)은 그림·차트로 만들지 않는다. 가이드를 받지 못했으면 이 점을 이용자에게 알리고, 계산이 필요한 값으로 보이는 것은 제안에서 뺀 뒤 그 이유를 적는다.
2. **원고에 있는 것만 그린다.** 원고에 근거가 없는 것을 정해야 하면 "가정"으로 표시하고 무엇을 정했는지 한 줄로 적는다. 이용자가 확인하기 전까지는 확정하지 않는다.
3. **실존 대상을 쓰지 않는다.** 실존 인물, 실제 기관 로고·상표, 알아볼 수 있는 실제 장소는 넣지 않는다. 과제는 가상 기관을 다루고, 실제 대상을 아는 응시자가 유리해지기 때문이다.
4. **그림 안에 글자를 넣지 않는다.** 이미지 생성 모델은 한글을 정확히 쓰지 못한다. 글자는 과제 지면에 쓴다. 지도·차트의 이름표는 편집기가 쓰므로 예외다.
5. **양식을 바꾸지 않는다.** 그림 때문에 쪽 수, 자료 번호, 표지의 "총 n장"이 바뀌면 안 된다. 한 자료에 넣는 그림·지도·차트 수(이미 있는 것 포함)는 요청에 상한이 주어지면 그 값을, 없으면 2개를 넘기지 않는다. 상한은 용역 양식마다 다르므로 부르는 쪽이 정한다.
6. **숫자는 계산 코드가 읽은 값을 쓴다.** 모델이 숫자를 옮겨 적다 틀리는 일을 막기 위해서다.

## 결과 형식

요청에 결과 틀(받을 칸 목록이나 JSON 모양)이 함께 오면 그 틀을 그대로 따른다. 부르는 프로그램은 그 틀로 화면을 만들기 때문에, 칸 이름이나 순서를 바꾸면 결과가 화면에 나오지 않는다. 틀에 맞지 않는 내용이 있으면 버리지 말고 틀이 허용하는 "추가 내용" 칸에 넣는다.

결과 틀이 없을 때는 항목마다 다음을 한 줄씩 적는다.

```
종류: 그림 | 지도 | 차트
위치: <자료 제목> / "<바로 앞 문단의 첫 15자>" 뒤
제목: <그림 자리 제목>
내용: <그릴 장면 / 넣을 항목 / 데이터 표와 차트 종류>
이유: <이 자리에 필요한 까닭, 한 문장>
가정: <원고에 근거 없이 정한 것, 없으면 "없음">
```

제안하지 않기로 한 곳도 이유가 분명하면 "제안 안 함: <위치> — <이유>"로 적는다. 이용자가 왜 빠졌는지 묻지 않아도 알 수 있게 하기 위해서다.
